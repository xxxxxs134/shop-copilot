# P7 计划书：Agent 场景强化——让产品"像 Agent"而不是"像后台"

> **动机**：对比 GitHub 上 10+ 电商 Agent 项目（EcoShop/DeskClaw/Resolvr AI/Retail-AI-Agent 等），核心差距不是功能缺失，而是**展示视角错误**——我们在展示"数据管理页面"，它们在展示"Agent 帮人干了什么"。评分标准 AI 深度 35% + 创新 25% = **60%**看的就是 Agent 场景感。
> **目标**：把产品从"电商运营后台"升级为"电商运营 AI Agent"——每个页面、每次交互都在说"Agent 在帮你干活"。

---

## 一、GitHub 参考项目对比

| 模式 | 代表项目 | 核心做法 | 我们现状 |
|---|---|---|---|
| **场景表格** | EcoShop / Skein Lite | "客户说X → Agent做Y → 结果Z"表格 | ❌ 只有功能列表 |
| **推理面板** | Resolvr AI / ShopAssist | 💭思考→🔍工具→📋结果 可展开展示 | ⚠️ 有步骤卡片但不突出 |
| **故事线演示** | Zip-Zap-Sold | 7步完整流程：理解→发现→决策→审批→购买→追踪→反馈 | ❌ 功能是散的 |
| **Skill 体系** | DeskClaw | 10个Skill每个是完整场景+安全门控 | ⚠️ 有工具但没包装成场景 |
| **场景案例** | Retail-AI-Agent | 10个完成的对话，输入+输出+trace | ❌ 没有场景库 |
| **主动洞察** | DeskClaw ops-digest | Agent 主动分析→邮件报告 | ❌ 纯被动等提问 |

## 二、改造方案（三块）

### 改造 1：场景叙事层（P0，对应创新性+实用性 25%）

**T1: README 场景表 + 定位句 + 对比表**

README 顶部加：
1. 一句话定位："店智 Copilot：中小电商运营者的 AI 工作伙伴——查数据、管退款、答规则、写文案，一个对话框全搞定。"
2. Agent 场景表（≥6 行）：

| 场景 | 你说 | Agent 做 | 你得到 |
|---|---|---|---|
| 📦 查订单 | "SO20261025016 到哪了" | 调 order_lookup 查状态 | 订单详情+建议 |
| 💰 退款 | "帮我退 80 元" | validate→预览→令牌→等确认 | 执行回执 |
| 📚 规则 | "DSR 评分怎么算" | RAG 检索 43 篇文档 | 回答+[1][2]溯源 |
| 📊 数据 | "退款率怎么样" | 查数据+分析 | 三张报表+建议 |
| ✍️ 文案 | [上传商品图] | GLM-4V 识别+文案 | 标题+卖点+描述 |
| 🔧 知识 | "这条规则过时了" | /kb 编辑→即时生效 | 一分钟更新 |

3. 对比表（传统后台 vs 通用客服 vs 店智 Copilot）

**T2: /workspace 加「Agent 今日洞察」卡片**

- 位置：KPI 卡下方
- 内容：AI 主动分析今日数据给 2-3 条洞察（退款率偏高原因/知识库更新建议/库存告警）
- 数据来源：get_snapshot + get_orders 实时计算（不硬编码）
- 新增组件 InsightCard.tsx + api_workspace.py 加 insights 字段

**T4: docs/scenarios.md 场景案例库**

- 10 个完整对话场景：用户输入→Agent推理链→工具调用→输出
- 分类：查订单(2)/退款(2)/规则(2)/数据(2)/文案(1)/异常(1)

### 改造 2：推理可视化（P0，对应 AI 深度 35%）

**T3: 对话页推理面板强化**

- 每个步骤卡片加 💭 推理理由："因为用户问了退款进度，所以调用 order_lookup"
- 步骤间箭头连线：工具A结果→触发工具B
- 底部汇总条："本次调用 3 个工具，耗时 2.1s"
- 可展开/收起推理链

**T5: SSE 推理时间线**

- 回复区域顶部加推理时间线：💭理解→🔍查单→📋发现退款中→💡建议
- 每步可点击展开详情

### 改造 3：定位明确化（P1，对应选题创新 10%）

包含在 T1 README 里（定位句+对比表）。
