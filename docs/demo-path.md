# 5 分钟演示路径

> 目标：用 5 分钟把「中小电商运营者的 AI 工作台」跑一遍：四类工作（看数据、查问题、处理售后、写文案）加知识库维护。
> 环境：本地双服务，前端 `http://localhost:3000`，FastAPI `http://127.0.0.1:8000`，数据来自 `data/store.db` 种子库。
> 口径：演示跑的是本地模拟数据，未接平台真实授权；文中订单号、金额、物流单号均可用文末 SQL 复核。

## 时间轴

| 时间 | 段落 | 入口 | 一句话 |
|---|---|---|---|
| 0:00 | 工作台（三件事） | `/workspace` | 今天要处理什么，一屏说完 |
| 1:00 | 查问题（退款率归因） | `/workspace` → `/chat` | 退款率 3.13%，哪几单卡住了 |
| 2:00 | 处理售后（查单 → 退款门控） | `/chat` | 先查 009 物流，再给 001 退 80 |
| 3:30 | 写文案（图生文案） | `/chat` | 一张商品图出标题、卖点、描述 |
| 4:30 | 知识库编辑即生效 | `/kb` → `/chat` | 改一句，重问答案就变 |

## 演示前 30 秒

1. 确认两个服务已起：`curl http://127.0.0.1:8000/health` 返回 ok，浏览器能打开 `http://localhost:3000/workspace`。
2. 备份种子库：`Copy-Item data\store.db data\store.demo.bak -Force`。演示里 001 会被退款，下一场开始前用 `Copy-Item data\store.demo.bak data\store.db -Force` 恢复。
3. 不要在演示当天重跑 `python -m backend.app.agent.seed_store`。它按 `date.today()` 生成单号前缀，会把 `SO20261027xxx` 变成当天日期，本文所有单号都会对不上。

## 0:00 工作台：今天先看这三件事

| 字段 | 内容 |
|---|---|
| URL | `http://localhost:3000/workspace` |
| 输入原文 | 无输入。开口念页头：「早上好，今天先看这三件事」。 |
| 预期界面 | 页头是标题、今天日期、右上角「问 AI」。下面 4 张 KPI：今日 GMV、订单数、退款率、转化率。左 2/3 是「Agent 今日洞察」和「Agent 发现 / 待办」，右 1/3 是「快捷操作」「最近会话」「知识库状态」。页面下半部「经营数据 · 近 30 天」里有「30 天经营趋势」，再往下是热销商品 Top 3、流量来源、订单状态三张卡。 |
| 预期结果 | 15 秒讲完三件事。待处理售后：待办 4 件，016 秦\*\* ¥199 退款中、017 许\* ¥129 退款中、011 蒋\* ¥119 被拒、013 韩\* ¥198 被拒。今日洞察：退款率 3.13%，高于 2.5% 告警线；库存告急，儿童保温杯仅 2 件，另有 1 个在售商品库存偏低。经营趋势：指「30 天经营趋势」的 GMV 与订单曲线。 |
| 失败兜底 | 页面出现「暂时拿不到经营数据」时点「重试」。仍为空，在另一个终端跑 `curl http://127.0.0.1:8000/health`，确认 8000 已起；没起就按 README 启动 uvicorn，回到页面再点「重试」，不要刷新整页。 |

## 1:00 查问题：退款率为什么涨

| 字段 | 内容 |
|---|---|
| URL | 从 `http://localhost:3000/workspace` 点右上角「问 AI」进入 `http://localhost:3000/chat`，也可直接打开 `/chat`。 |
| 输入原文 | `最近退款率为什么涨了？帮我看看哪几单卡住了` |
| 预期界面 | 顶栏模式是「Agent 模式」，消息上方出现意图 chip（数据查询，路由到 Agent 工具）。「📊 数据查询」「📦 订单查询」步骤卡先后出现，点卡片展开能看到参数、耗时和工具返回 JSON。回答按「退款中 / 被拒 / 已完成」分组，结尾给下一步建议。 |
| 预期结果 | 回答给出退款率 3.13%（种子库最新一天 2026-10-27），点名 016、017 两笔退款中，并建议先盯到账时效、再复核两笔被拒的拒因。讲解口径可补一句：近 30 天退款率在 1.31%~3.14%，均值 2.29%。 |
| 失败兜底 | 没有自动切到 Agent，手动点顶栏「Agent 模式」再发一次。工具没返回，打开「业务数据」（`/data`）用状态筛选「退款中」看到 016、017，回 `/chat` 问 `SO20261027016 和 SO20261027017 的退款进度和原因`。 |

## 2:00 处理售后：查单 → 退款门控

| 字段 | 内容 |
|---|---|
| URL | `http://localhost:3000/chat`（Agent 模式） |
| 输入原文 | 第 1 句 `SO20261027009 到哪了`；第 2 句 `SO20261027001 到哪了`；第 3 句 `帮我退 80 块`；第 4 句 `确认`。 |
| 预期界面 | 右侧滑出「订单详情」，先显示 009：郑\*、不锈钢保温饭盒 ×2、¥178、已发货；「📦 订单查询」卡展开后，JSON 里有 `carrier: 圆通速递`、`tracking_no: YT9182736455102`。接着查 001，新的订单卡显示张\*、纯棉基础款T恤 ×2、¥159.8、已付，卡上有「💰 处理退款」。发「帮我退 80 块」后出现「💰 退款流程」步骤卡和校验预览：退款 ¥80.00、剩余 ¥79.80、确认退款吗。回「确认」后出执行回执：订单、退款、剩余、售后单号、时间、已退款。 |
| 预期结果 | 两段式门控讲清楚：第一段 validate 只校验订单存在、已付款、未退过、金额不超过实付、在 7 天售后期内，通过才发 10 分钟有效的一次性令牌；第二段 execute 凭令牌落库，更新订单和售后单。001 是 2026-10-26 的 paid 单，退 80 后剩 79.8，订单状态变已退款。再确认一次只回「已退款」，不会重复扣款。 |
| 失败兜底 | 模型只回文字没调工具，展开 001 订单卡点「💰 处理退款」，金额改成 80，点「下一步：校验」，再点「确认退款」，弹窗走同一套 `/v1/refund/validate` 和 `/v1/refund/execute` 门控。若校验提示超过 7 天售后期，说明种子库被换过单号或日期，用 `Copy-Item data\store.demo.bak data\store.db -Force` 恢复后刷新页面重试。 |

## 3:30 写文案：一张图出标题、卖点、描述

| 字段 | 内容 |
|---|---|
| URL | `http://localhost:3000/chat`（Agent 模式） |
| 输入原文 | 点输入框左侧 🖼️ 上传一张保温杯白底图；识别完成后接着发 `给这个保温杯写个标题、卖点和描述，今晚挂活动页`。 |
| 预期界面 | 输入框上方出现「图片识别结果」卡，含标题、卖点列表、描述。发送后出现「✍️ 文案生成」步骤卡。回答按标题、卖点、短描述三块输出，标题自动回填输入框。 |
| 预期结果 | 得到 1 条标题、3 条卖点、1 段短描述，可直接复制到活动页；全程不碰订单和库存。 |
| 失败兜底 | 视觉接口没配 key 时报「图片识别失败」，不传图，直接在 Agent 模式发 `给纯棉基础款T恤写标题、卖点和描述，今晚挂活动页`，同样出「文案生成」卡。文案也没返回，把商品和价格写进问题再发 `纯棉基础款T恤 79.9 元，写 3 条卖点和一段 60 字描述`。 |

## 4:30 知识库：编辑即生效

| 字段 | 内容 |
|---|---|
| URL | `http://localhost:3000/kb`，验证回 `http://localhost:3000/chat`，顶栏切「RAG 问答」。 |
| 输入原文 | 打开《退款率过高的后果与控制》的切片，把 `一般建议将退款率控制在类目均值以内` 改成 `一般建议将退款率控制在 8% 以内`。保存后回 `/chat` 切「RAG 问答」，问 `退款率控制在多少比较安全？` |
| 预期界面 | 页头「知识库」加「编辑切片，保存即生效」。统计卡显示 43 篇文档、43 个切片、检索得分 90%。点文档行展开 1 个 textarea。改动后底部显示「有未保存的修改」。点「保存」按钮变「保存中…」，成功后闪「已保存」，状态回到「与索引一致」。点「重建索引」出现 toast「索引重建完成 · 耗时 x.x 秒 · 43 个切片」。回 `/chat` 后回答里出现 8%。 |
| 预期结果 | 保存会 PUT 该切片，重新嵌入并让检索单例失效，下一次提问直接读到新文本。回答给出「8%」，`[1]` 仍能溯源到《退款率过高的后果与控制》。 |
| 失败兜底 | 保存报「保存失败：…」，先确认 8000 在跑且 `data/index/local/chunks.lance` 存在，再点一次「保存」，草稿还在 textarea 里。回答仍是「类目均值」，刷新 `/chat` 重问；仍旧就回 `/kb` 再保存一次再问。 |

操作顺序：

1. `/kb` 点《退款率过高的后果与控制》。
2. 展开切片，页面里只有 1 个 textarea。
3. 把「类目均值」改成「8%」，底部出现「有未保存的修改」。
4. 点「保存」，等按钮从「保存中…」变回「保存」，行内闪「已保存」，状态是「与索引一致」。
5. 回 `/chat` 切「RAG 问答」问 `退款率控制在多少比较安全？`，回答出现 8%。
6. 回 `/kb` 点「重建索引」，等 toast「索引重建完成」，收尾复位。

**顺序提醒**：「保存」这一步已经让改动生效，「重建索引」是按 `data/raw` 全量重跑，会把只在索引层的编辑还原。演示时先保存并验证，最后再点「重建索引」做收尾复位，顺便把语料恢复原样，方便下一场。
