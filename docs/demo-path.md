# 5 分钟演示路径

> 目标：用 5 分钟把「面向客户的电商智能客服 Agent」跑一遍：售前咨询与推荐、售后查单与退款门控、投诉升级工单，最后演示商家知识库编辑即生效。
> 环境：本地双服务，前端 `http://localhost:3000`，FastAPI `http://127.0.0.1:8000`，数据来自 `data/store.db` 种子库。
> 口径：演示跑的是本地模拟数据，未接平台真实授权；文中订单号、金额、物流单号均可用文末 SQL 复核。

## 时间轴

| 时间 | 段落 | 入口 | 一句话 |
|---|---|---|---|
| 0:00 | 客服对话首页 | `/chat` | 演示导览 + 3 分钟路线，点「开始」直接办事 |
| 0:45 | 售前咨询与推荐 | `/chat` | 问礼物，Agent 查商品 + 知识库给推荐 |
| 1:45 | 售后查订单 | `/chat` | 一句订单号，订单卡与物流直接摊开 |
| 2:45 | 退款门控 | `/chat` | 预览 ¥80 与剩余 ¥79.8，确认后才执行 |
| 3:45 | 投诉升级 | `/chat` | 情绪识别 → 生成工单号、类别、紧急度 |
| 4:30 | 知识库编辑即生效 | `/kb` → `/chat` | 改一句，重问答案就变 |

## 演示前 30 秒

1. 确认两个服务已起：`curl http://127.0.0.1:8000/health` 返回 ok，浏览器能打开 `http://localhost:3000/chat`。
2. 备份种子库：`Copy-Item data\store.db data\store.demo.bak -Force`。演示里 001 会被退款，下一场开始前用 `Copy-Item data\store.demo.bak data\store.db -Force` 恢复。
3. 不要在演示当天重跑 `python -m backend.app.agent.seed_store`。它按 `date.today()` 生成单号前缀，会把 `SO20261027xxx` 变成当天日期，本文所有单号都会对不上。
4. 用新会话演示（会话栏「新建」），避免历史上下文干扰 Router 判断。

## 0:45 售前咨询：商品推荐 + 知识库引用

| 字段 | 内容 |
|---|---|
| URL | `http://localhost:3000/chat` |

## 2:45 退款门控：预览 → 确认 → 回执

| 字段 | 内容 |
|---|---|
| URL | `http://localhost:3000/chat` |
| 输入原文 | 第 1 句 `SO20261027001 到哪了`；第 2 句 `帮我退 80 块`；第 3 句 `确认`。 |
| 预期界面 | 001 订单卡：张\*、纯棉基础款T恤 ×2、¥159.8、已付。发「帮我退 80 块」后面板出现售后 Agent 的 `refund_flow` 工具轨迹，并给出校验预览：退款 ¥80.00、剩余 ¥79.80、确认退款吗。回「确认」后出执行回执：订单号、退款金额、剩余、售后单号、时间。 |
| 预期结果 | 第一段 validate 校验订单存在、已付款、未退过、金额不超过实付、在 7 天售后期内，通过才发 10 分钟有效的一次性令牌；第二段 execute 凭令牌落库。再发一次「确认」只回「已退款」，不重复扣款。 |
| 失败兜底 | 模型只回文字没调工具：再发一次并明确「先校验订单 SO20261027001，再退 80」；回「确认」仍无回执，检查请求是否带上同一 `thread_id` 与此前对话历史。提示超期：种子库被换过，恢复 `store.demo.bak` 后重试。 |

## 4:30 知识库：编辑即生效

| 字段 | 内容 |
|---|---|
| URL | `http://localhost:3000/kb`，验证回 `http://localhost:3000/chat`。 |
| 输入原文 | 打开《退款率过高的后果与控制》的切片，把 `一般建议将退款率控制在类目均值以内` 改成 `一般建议将退款率控制在 8% 以内`。保存后回 `/chat` 问 `退款率控制在多少比较安全？` |
| 预期界面 | 页头「知识库」加「编辑切片，保存即生效」。统计卡显示 43 篇文档、43 个切片、检索得分 90%。点文档行展开 textarea。改动后底部显示「有未保存的修改」，点「保存」按钮变「保存中…」，成功后闪「已保存」，状态回到「与索引一致」。 |
| 预期结果 | 保存会 PUT 该切片、重新嵌入并让检索单例失效；下一次提问直接读到新文本，回答给出「8%」，`[1]` 仍能溯源到《退款率过高的后果与控制》。 |
| 失败兜底 | 保存报错：确认 8000 在跑且 `data/index/local/chunks.lance` 存在，再点一次保存，草稿还在 textarea。回答仍是「类目均值」：回 `/kb` 再保存一次，或点「重建索引」后重问。 |

操作顺序：

1. `/kb` 点《退款率过高的后果与控制》。
2. 展开切片，页面里只有 1 个 textarea。
3. 把「类目均值」改成「8%」，底部出现「有未保存的修改」。
4. 点「保存」，等按钮从「保存中…」变回「保存」，行内闪「已保存」，状态是「与索引一致」。
5. 回 `/chat` 问 `退款率控制在多少比较安全？`，回答出现 8%。
6. 回 `/kb` 点「重建索引」，等 toast「索引重建完成」，收尾复位。

**顺序提醒**：「保存」这一步已经让改动生效，「重建索引」是按 `data/raw` 全量重跑，会把只在索引层的编辑还原。演示时先保存并验证，最后再点「重建索引」做收尾复位，顺便把语料恢复原样，方便下一场。
