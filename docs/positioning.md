# 店智 Copilot — 产品定位

> 本文件是全站唯一叙事真源。README、演示脚本、场景库、UI 文案与答辩口径均以此为准；冲突时改文档，不改这里。

## 一句话

看数据、查问题、处理售后、写文案——一个对话框全搞定。

## 定位

- 产品名：店智 Copilot
- 品类：中小电商运营者的 AI 工作台
- 形态：浏览器打开即用的对话式工作台，左侧四个入口（工作台 / 对话 / 数据 / 知识库）
- 不是什么：不是通用聊天机器人，不是传统客服工单系统，不是数据看板工具

## 目标用户

目标用户：1–5 人小团队的店主/运营，没有专职数据分析与客服。

他们的典型一天：

- 早上想知道昨天/今天卖得怎么样，哪条链路出问题了；
- 白天被退款、物流、差评、投诉打断，需要边查边处理；
- 上新或做活动时要写标题、卖点、描述；
- 平台规则常变，需要一个能查到原文依据、还能自己维护的知识库。

## 四类工作

### 1. 看数据

用一句话拿到今日 GMV、订单数、退款率、转化率与 30 天趋势；异常点由 Agent 主动指出，而不是让人自己翻表格。

### 2. 查问题

对"退款率怎么涨了""哪批订单卡住了"这类问题做归因：查业务数据、关联订单与售后单、给出可执行建议，而不是只回一段泛泛的分析。

### 3. 处理售后

查订单、查物流、退款、改地址、拦截物流、退换货、投诉处理方案。敏感操作走两段式门控：`validate`（后端校验并给出预览与一次性令牌）→ 用户确认 → `execute`；模型不直接动钱。

### 4. 写文案

上传商品图或给一句描述，生成标题、卖点与详情描述；也可基于知识库里的平台规则做合规自查。

## 三个差异点

1. 咨询即办理：不是"告诉你怎么做"，而是在对话里把操作做完；退款/改地址/拦截物流/退换货均有两段式门控（validate→confirm→audit）。
2. 有据可查：RAG 知识库（当前 43 篇种子语料）+ 混合检索（BM25 + 向量 RRF），回答带 `[n]` 角标，可点开核对原文。
3. 知识库编辑即生效：`/kb` 页面可直接编辑切片，保存后重新嵌入并失效旧检索单例，不需要改代码或重启。

## 边界

客服/售后是工作台里的一个场景，不是产品身份。

对外介绍时，先讲"运营工作台"，再讲"其中售后处理能咨询即办理"；不要把产品说成"智能客服系统"，也不要把"转人工"当成卖点——本产品做的是"生成处理方案（情况摘要 + 建议动作 + 可复制话术）"，由运营自己决定怎么发。

## 口径映射

| 旧表述 | 新表述 | 适用范围 |
|---|---|---|
| 智能客服 Agent / 智能客服系统 | 中小电商运营者的 AI 工作台 | 全站身份表述、README 首段、答辩开场 |
| 一键转人工 / 转人工协同 | 投诉处理：情况摘要 + 建议动作 + 可复制话术 | README、场景库、UI 文案 |
| 客服工作台 | 运营工作台 | 全局导航、页面标题 |
| 电商运营 AI 智能助手 | 运营工作台（AI 能力是手段，不是身份） | metadata、副标题 |

## 禁止表述

以下短语不得作为产品身份出现在 README、文档标题、页面标题、演示旁白中：

- 智能客服 Agent
- 智能客服系统
- 一键转人工
- 客服工作台

允许出现的唯一语境：与同类方案做对比时，说明"我们不是……"。

## 一句话电梯稿

店智 Copilot 是给 1–5 人电商小团队的 AI 工作台：早上看一眼就知道今天要处理什么，白天在对话里直接查单、退款、改地址、拦截物流，晚上要用数据或写文案也不用换工具。敏感操作有后端门控，回答有知识库溯源，知识库还能自己改、改完立即生效。
