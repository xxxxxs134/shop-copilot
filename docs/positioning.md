# 店智 Copilot — 产品定位

> 本文件是**全站唯一事实源**：README、演示脚本、场景库、UI 文案、技术文档都以此为准；冲突时以本文件为准。

## 一句话

> 面向客户的电商**全链路智能客服 Agent**——售前帮你选品推荐、查库存，售后帮你查订单、办退款退货、处理投诉。

## 定位

- 产品名：店智 Copilot
- 品类：电商智能客服 Agent（售前 + 售后全链路）
- 形态：客户对话入口（`/chat`）+ 商家知识库（`/kb`）两个入口
- 是什么：基于 LangGraph 的多 Agent 客服，Router 分流 + 售前/售后专业 Agent + 终审防幻觉
- 不是什么：不是运营后台 / 数据看板；不做 ERP 式全量 CRUD

## 目标用户

- **C 端客户**：下单前来咨询商品、比价、选款、问库存；下单后来查物流、办退款退货、投诉。
- **B 端商家**：在知识库里维护商品知识、售后政策，Agent 据此回答客户。

客户的典型一天：
- 想给父母挑礼物，问"有什么合适的、多少钱、有没有货"。
- 下单后催"我的订单到哪了"。
- 收到货不满意，问"怎么退款 / 退货"。
- 物流超时急了，直接来投诉。

## 高频工作（两类场景）

### 1. 售前（下单前）
- 商品咨询：价格、规格、卖点、适用场景
- 智能推荐：根据客户需求（预算/品类/场景）推荐商品并给理由
- 库存查询：有没有货、剩多少

### 2. 售后（下单后）
- 订单查询：查订单状态、物流进度
- 退款退货：退款（校验 → 客户确认 → 执行）、退货、改地址、拦截物流
- 投诉处理：安抚情绪 + 情况摘要 + 建议动作 + 工单升级

## 核心能力

1. **多 Agent 编排**：LangGraph StateGraph，Router（意图路由）→ 售前/售后专业 Agent → 终审（response_review）。
2. **工具隔离**：售前和售后各自独立的工具集，职责边界清晰，不让一个 Agent 拥有所有权限。
3. **有据可查**：RAG 检索知识库，回答带 `[n]` 角标，可点开核对原文；终审只保留有工具证据的内容，防幻觉。
4. **过程透明**：Agent 每一步工具调用都可视化为步骤卡片。
5. **知识库即时生效**：商家改一条商品知识/售后政策，保存即重新嵌入并失效旧检索。

## 边界

- 客服是核心，不做运营后台 / 数据看板 / ERP 全量 CRUD。
- 敏感操作（退款/改地址/拦截）走「校验 → 客户确认 → 执行」两段式门控，模型不直接动钱。
- 演示数据为本地模拟数据（种子库），未接平台真实授权；接真实电商数据库只需实现一个 `DataProvider` 接口。

## 一句话自述

> 店智 Copilot 是一个面向客户的电商智能客服 Agent：客户在对话里咨询商品、查订单、办退款退货、投诉，Agent 自动判断售前还是售后，调用对应工具给出有据可查的回答；敏感操作必须客户确认后才执行。商家只需在知识库里维护商品知识和售后政策，Agent 就能持续接客。
