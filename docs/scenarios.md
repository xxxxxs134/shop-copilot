# 场景案例库：店智 Copilot 的 10 段对话

> 覆盖意图分流、RAG 检索、订单/商品/售后查询、退款两段式、合规检查、经营分析、图生文案、知识库兜底。
> 每个场景标注意图分类、路由走向、推理链与技术点，可直接当演示脚本或验收用例跑。
> 订单号、商品、售后单均来自本地种子库（`python -m backend.app.agent.seed_store`），金额与状态可复现。

## 场景 1：查订单状态

**用户输入**："SO20261025010 到哪了？客户催第三遍了"
**意图分类**：data
**路由**：Agent 工具（意图 chip：数据查询 · 路由 → Agent 工具 · 已按意图切换）
**Agent 推理链**：
1. 💭 用户给了具体订单号，还带着"客户在催"的情绪，要的不只是状态，还得有一句能回给买家的话。
2. 🔍 order_lookup(order_id="SO20261025010") → 冯** 的单，商品是宠物自动饮水机 ×1，实付 159 元，状态 shipped，物流已揽收，下单 1 天。
3. 💡 整理成订单卡片，附上预计送达时间，再补一句安抚话术，让用户复制就能回买家。

**输出**：
> 订单 SO20261025010 · 宠物自动饮水机 ×1 · 实付 159 元
> 状态：已发货（shipped），物流已揽收，预计 2 天内送达。
> 建议话术："亲，您的饮水机已经发出啦，物流单号是 SF 开头那个，预计后天到，让您久等了。"

**技术点**：意图分类（/v1/intent 单次调用，temperature=0）+ RAG 模式自动切 Agent + order_lookup 精确查询 + SSE 步骤卡片（工具名、参数、返回 JSON 可展开）

## 场景 2：查退款进度

**用户输入**："最近退款这块什么情况？有没有卡住的单子"
**意图分类**：data
**路由**：Agent 工具
**Agent 推理链**：
1. 💭 用户问的是面上的进度，不是某一单。得按状态各拉一遍，归成几堆，卡住的单独点出来。
2. 🔍 order_lookup(status="refunding") → SO20261025016（无线蓝牙耳机 199 元）、SO20261025017（厨房置物架 129 元）两笔退款中，各挂着一条售后单；再补查 refunded 与被拒的售后，凑齐六条。
3. 💡 按"退款中 / 被拒 / 已完成"分三张表，底下给三条下一步动作。

**输出**：
> **退款中（2 笔）**：SO20261025016 耳机 199 元 · SO20261025017 置物架 129 元
> **被拒（2 笔）**：拒因分别是超售后期、金额与实付不符
> **已完成（2 笔）**：SO20261025018、SO20261025019 已原路退回
> 建议：先盯退款中那两笔的到账时效；被拒的两笔复核拒因，能协商的走部分退；这两周退款率 2.8%，快到警戒线了。

**技术点**：order_lookup 多状态过滤 + 订单与 aftersales 关联返回 + 多步工具编排（最多 5 步上限内完成）+ 表格化结构输出

## 场景 3：退款两段式，正常流程

**用户输入**："SO20261025004 这单客户要退 80 块，帮我处理下"
**意图分类**：policy（敏感操作，按合规类路由）
**路由**：Agent 工具
**Agent 推理链**：
1. 💭 退款是敏感操作，绝不能一口气回答完就退。先让后端校验，拿到预览和令牌，再停下来问人。
2. 🔍 refund_flow(action="validate", order_id="SO20261025004", amount=80) → 逐条过规则：订单存在 ✓ 已付款 ✓ 未退过 ✓ 80 ≤ 实付 199 ✓ 下单 5 天在 7 天售后期内 ✓；返回确认预览 + 10 分钟有效的一次性令牌。
3. 💡 把预览原样复述给用户，问"确认退款吗？"，本轮到此结束，等回复。

**用户（第二轮）**："确认"
**Agent 推理链（续）**：
1. 💭 用户明确同意，凭令牌执行。
2. 🔍 refund_flow(action="execute", order_id="SO20261025004", token="…") → 校验令牌（存在、未过期、订单匹配）→ 更新售后单与订单状态 → 令牌即刻作废；返回执行回执。
3. 💡 输出回执卡片。若用户再说一次"确认"，走幂等分支，只回一句已退款。

**输出**：
> **预览**（第一轮）：SO20261025004 · 无线蓝牙耳机 ×1 · 本次退 80.00 元 · 实付 199.00 元 · 退款后累计已付 119.00 元。确认退款吗？
> **回执**（第二轮）：✓ 退款已执行。售后单号 AS20261025004 · 退款金额 80.00 元 · 状态 已退款 · 时间 2026-10-25 14:32。重复提交只会拿到这条回执，不会退第二次。

**技术点**：refund_flow 两段式（validate 发令牌 → execute 凭令牌）+ 校验规则全在后端（不信任模型传参）+ token 10 分钟 TTL、一次性消费 + 执行幂等 + 跨轮对话天然 resume

## 场景 4：退款被拒，金额超限

**用户输入**："SO20261025010 退 418 吧，客户拿别家的截图来要差价"
**意图分类**：policy
**路由**：Agent 工具
**Agent 推理链**：
1. 💭 金额比实付还高，八成过不了。别替规则说话，先让后端打回来，再给合规的路子。
2. 🔍 refund_flow(action="validate", order_id="SO20261025010", amount=418) → ok=false，violations=["退款金额 418.0 超过实付金额 159.0"]，未签发令牌。
3. 💡 转述拒因，说清只能按实付退，另外给两条不违规的替代方案。

**输出**：
> 这单退不了 418。后端校验打回：退款金额 418.0 超过实付金额 159.0。
> 合规做法有两个：一是按实付 159 元整单退；二是走价保流程补差价（补的是差价不是退款）。要走哪个我接着办。

**技术点**：validate 拒绝分支 + violations 列表原样转述 + 业务校验在后端（模型说了不算）+ 拒绝不中断对话（作为 tool result 回给模型继续答）

## 场景 5：DSR 规则问答

**用户输入**："DSR 评分到底怎么算的？客户老拿这个说事，我想讲清楚点"
**意图分类**：knowledge
**路由**：RAG 检索（意图 chip：知识问答 → 检索，模式留在 RAG）
**Agent 推理链**：
1. 💭 规则解释类问题，走知识库检索。回答要能溯源，客户较真的时候好对质。
2. 🔍 RAG 混合检索（jieba BM25 + 向量 RRF 融合）→ 命中《DSR 评分规则解读》《体验分与店铺权益》等 43 篇中的 2 篇，召回 4 个切片，按 RRF 排序取前 3。
3. 💡 生成回答，句尾挂 [1][2] 角标，鼠标点开就是来源卡片。

**输出**：
> DSR 是三项的合称：描述相符、服务态度、物流速度，取近 180 天买家评分的均值 [1]。它不等于体验分，体验分还看退款率、纠纷率这些指标 [2]。想把分拉回来，优先处理差评和退款纠纷，短期见效的是物流时效和客服响应 [1][2]。
> （点击 [1] 弹出来源卡片：《DSR 评分规则解读》分类"平台规则"，原文片段可见）

**技术点**：BM25 + 向量 RRF 融合检索 + [1][2] 引用角标 + CitationCard 溯源（标题 / 分类 / 原文片段）+ 流式 Markdown 渲染

## 场景 6：平台违规规则问答

**用户输入**："我想搞个好评返现，送包纸巾让买家给五星，这样搞会不会有事？"
**意图分类**：policy
**路由**：Agent 工具（policy_check + kb_search）
**Agent 推理链**：
1. 💭 这是合规问题，光背规则不够，用户要的是"能不能干"的判断和替代路子。
2. 🔍 policy_check(场景="好评返现送礼品") → 风险等级 高：属于诱导好评，平台规则明确禁止，可能被判虚假交易或扰乱评价秩序；再 kb_search("诱导好评 违规 处罚") → 命中《常见违规行为》切片，取两段作依据。
3. 💡 输出风险等级 + 规则出处 + 不踩线的替代方案。

**输出**：
> ⚠️ 风险等级：高。好评返现属于诱导好评，平台规则明确禁止，处罚轻则删除评价、扣分，重则按虚假交易处理 [1]。
> 想要好评，合规的做法是把体验做上去：发货快一点、售后响应快一点、随包放张关怀卡（只写感谢，不提好评）[2]。
> 活动报名、改价这类场景也可以让我先过一遍合规。

**技术点**：policy_check 风险分级 + kb_search 引用溯源 + 工具组合调用（合规检查与知识检索配合）+ 风险提示与可执行建议并列输出

## 场景 7：经营数据分析

**用户输入**："帮我看看这一个月店铺跑得怎么样，哪块要改"
**意图分类**：data
**路由**：Agent 工具
**Agent 推理链**：
1. 💭 用户要的是复盘，不是报数。先拉快照，再对比着看，最后落到能改的动作上。
2. 🔍 data_query() → 30 天快照：GMV、订单数、访客数、转化率 4.1%、退款率 2.8%、流量来源分布（免费搜索 / 推荐 / 活动 / 付费）；返回体带 source: sqlite，标明数据来自本地种子库。
3. 💡 拆成核心指标表，指出两处短板，给三条按优先级排的建议。

**输出**：
> **近 30 天**：GMV 稳中有升，订单数环比小涨，转化率 4.1%（正常区间 3.4%~4.8%）。
> **两处要改**：一是退款率 2.8%，贴近上沿；二是免费搜索流量占比偏低，太依赖活动流量。
> **建议**：1. 优先清退款中的两笔，跟踪退货物流；2. 主推款标题和主图过一遍，把搜索流量做起来；3. 活动流量别停，但要盯住转化，别买了流量接不住。
> （数据来源：sqlite 本地种子库，未接平台真实授权）

**技术点**：data_query 经营快照 + DataProvider 插件化（返回体标注 source，换真实店铺只改一个类）+ 指标对比分析 + 数据到建议的生成链路

## 场景 8：热销品与库存

**用户输入**："哪些东西卖得最好？顺便看看库存撑不撑得住下个月"
**意图分类**：data
**路由**：Agent 工具
**Agent 推理链**：
1. 💭 两件事：销量排行和库存水位。一个查经营数据，一个查商品库，得两个工具配合。
2. 🔍 data_query() → 近 30 天商品销量 Top：纯棉基础款T恤、便携式充电宝、加厚珊瑚绒毯；product_lookup(keyword="") 按品类扫一遍库存 → 桌面收纳盒剩 4 件、儿童保温杯剩 2 件，触发低库存提示。
3. 💡 热销榜和断货风险摆在一起看，给出补货节奏。

**输出**：
> **卖得最好**：纯棉基础款T恤（库存 320）、便携式充电宝（180）、加厚珊瑚绒毯（75）。
> **断货风险**：儿童保温杯仅剩 2 件、桌面收纳盒剩 4 件，这两款还是走量款，一周内大概率断。
> **建议**：保温杯和收纳盒先补一批，补货量按近两周日销 ×20 天估；老款帆布双肩包已下架零库存，别放进活动页。

**技术点**：product_lookup（价格 / 库存 / 上下架状态）+ data_query 组合调用 + 低库存自动提示 + 多工具结果交叉比对

## 场景 9：商品图生成文案

**用户输入**：（上传一张保温杯白底图）"给这个杯子写个标题和卖点，今晚要挂活动页"
**意图分类**：copywriting
**路由**：Agent 工具（GLM-4V 视觉端点）
**Agent 推理链**：
1. 💭 用户给的是图不是文字。先让视觉模型把商品看明白，再按活动页的文案结构出稿，长度和卖点条数得卡平台限制。
2. 🔍 GLM-4V 识别图片 → 白底保温杯，不锈钢材质，带杯盖与便携提手，容量中大；再调 copywriting，按"标题 + 卖点 + 短描述"结构生成。
3. 💡 输出文案卡片，可一键回填输入框，用户改两个字就能用。

**输出**：
> **标题**：316不锈钢保温杯 大容量便携水杯 12小时保温
> **卖点**：① 316 内胆，装水不串味；② 12 小时长效保温，冬天出门也够喝；③ 一手可握的提手设计，通勤带娃都方便。
> **短描述**：给全家人用的保温杯，材质安全，保温能打，随身带着不费劲。
> （文案已自动填入输入框，可直接编辑）

**技术点**：GLM-4V 多模态识别（图 → 商品属性）+ copywriting 工具生成 + 标题字数与卖点结构受控 + 结果卡片回填输入框 + 语音输入可接续（Web Speech API）

## 场景 10：知识库未覆盖，兜底回答

**用户输入**："找个主播带货一般给多少坑位费？提点比例多少合适？"
**意图分类**：knowledge
**路由**：RAG 检索（未命中有效内容，走兜底）
**Agent 推理链**：
1. 💭 知识问答类，先检索。但这个问题偏市场行情，知识库里未必有。
2. 🔍 RAG 检索 → 最高分切片来自《直播开播话术》，讲的是开播流程和话术，跟坑位费行情不沾边，相似度低于可用阈值。
3. 💡 不编数字。明说没覆盖，把沾边的已有内容指出来，再给一条把知识补上的路径。

**输出**：
> 这个我答不了，知识库里没有坑位费和提点比例的行情数据。瞎报一个数容易把你带偏，我就不编了。
> 能答的有一块：直播开播的流程和话术我这有 [1]，可以先看这个把开播盘子搭起来。
> 坑位费建议你按品类去问几家 MCN 对比着看。如果拿到了靠谱的报价区间，扔进知识库（侧边栏「知识库」），我下次就能帮你算账了。

**技术点**：检索低置信兜底 + 不瞎编的诚实原则 + 相近内容引导（不空手而归）+ /kb 补录闭环（编辑切片 → 重嵌入 → 重建索引，一分钟内下次可答）
