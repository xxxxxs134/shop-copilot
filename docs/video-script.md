# 店智 Copilot 演示视频脚本（三段式 · 总时长 ~7.5 min）

> 用途：录屏 + 后期配音，按三段顺序录制。每镜四栏：画面 / 台词 / 时长 / 对应文件。
> **总时长 450s ≈ 7 分 30 秒**（要求区间 5-8 分钟）。
> 分段：一、效果演示 200s（~3 min）｜二、功能细节 150s（~2.5 min）｜三、技术架构 100s（~1.5 min）

## 一、效果演示（~3 min，200s）

### 1. 开场 + RAG 问答带 [1] 溯源

- 画面：首页双栏布局，左栏会话列表，右栏聊天窗口。RAG 模式输入「淘宝 DSR 评分包含哪三项？」，回答流式输出，句尾出现 [1][2] 角标，鼠标划过角标停一下（点击留到第二部分镜头 9 再拍）。
- 台词：「先看效果。这是店智 Copilot 的 RAG 问答，内置 40 篇电商运营知识库。问一个规则类问题，回答照着检索到的原文写，句尾带 [1][2] 角标，哪句话来自哪篇文档，一眼对得上。碰到知识库没覆盖的问题，它会直说没覆盖，不瞎编。卖家最怕 AI 张口就来，这里每句话都有出处。」
- 时长：50s
- 对应文件：app/page.tsx、components/ChatWindow.tsx、components/MarkdownText.tsx、backend/app/rag/retrieve.py

### 2. 意图分流 chip：问「查订单」自动切 Agent

- 画面：仍是 RAG 模式，输入「帮我查一下订单退款进度」。发送瞬间，气泡上方弹出小徽章「意图：数据查询 · 路由 → Agent 工具」，模式徽章从 RAG 自动跳成 Agent，回答改由工具查询给出。补拍一条对照：问「DSR 是什么」，徽章显示「知识问答 → 检索」，模式留在 RAG。
- 台词：「同一个输入框，模式不用你挑。发『帮我查一下订单退款进度』，系统在生成回答的同时先做一次意图分类，气泡上方直接亮出徽章：意图是数据查询，路由到 Agent 工具，模式也自动切了过去。换回『DSR 是什么』，徽章写知识问答、走检索，模式留在 RAG。该查数的去查数，该翻资料的翻资料，用户不用懂这些区别。」
- 时长：40s
- 对应文件：backend/app/agent/intent.py、backend/app/api_intent.py、lib/intentClient.ts、components/ChatWindow.tsx

### 3. Agent 查数据并给建议

- 画面：切到 Agent 模式，输入「查店铺今日数据并给建议」。步骤卡片逐张出现：📊 数据查询，副标题是参数摘要，状态从「运行中」变「✓ 完成」，点「详情」可展开返回结果；两张卡片后流式输出分析报告（表格 + 建议清单 + 优先动作）。
- 台词：「Agent 模式跑的是手写 ReAct 循环，调什么工具、调几次，模型自己决定。这里它先查整体经营数据，再查热销品和流量来源，两张步骤卡片实时弹出，最后给出转化率诊断和带优先级的建议。先查数、再分析、后建议，跟人类运营一个路子，而且每一步都摊开给你看。」
- 时长：40s
- 对应文件：backend/app/agent/loop.py、backend/app/agent/tools/__init__.py、components/AgentSteps.tsx、lib/agentRun.ts

### 4. 退款两段式确认

- 画面：输入「订单（用种子里真实存在的订单号）申请退 80 元，帮我处理」。第一轮：Agent 调 refund_flow 校验，回复预览（订单号 / 金额 / 商品 / 已退金额）并问「确认退款吗？」，此时停下不动；第二轮：输入「确认」，返回执行回执。补拍一条反例：金额填大，返回违规原因列表。
- 台词：「退款这种敏感操作，做成了两段式。第一轮只校验：订单在不在、付没付过、金额超没超、过没过售后期。全过了才发一个 10 分钟有效的确认令牌，把预览复述给你，然后停下来等。你说『确认』它才真正执行，说『不用』就什么都不动，就算重复执行，也只会回你一句已退款。校验规则全在后端，模型说了不算。」
- 时长：45s
- 对应文件：backend/app/agent/tools/__init__.py（refund_flow）、backend/app/agent/data_provider.py、backend/app/agent/seed_store.py

### 5a. 图生文案

- 画面：点输入框旁 🖼️，上传提前备好的商品白底图 → 返回标题 / 卖点 / 描述卡片 → 自动填入输入框，改两个字再发送。
- 台词：「传一张商品图，视觉模型直接给出标题、卖点和描述，填进输入框，改一改就能发。」
- 时长：15s
- 对应文件：app/api/vision/route.ts、components/ChatWindow.tsx

### 5b. 语音输入

- 画面：点 🎤 说「帮我看看退款率太高怎么办」→ 文字上屏 → 发送。
- 台词：「不想打字就点麦克风，说话也能提问。」
- 时长：10s
- 对应文件：components/ChatWindow.tsx（浏览器 Web Speech API）

## 二、功能细节（~2.5 min，150s）

### 6. 知识库管理页：改一块，马上生效

- 画面：侧边栏底部点「知识库」进入 /kb → 文档表（标题 / 分类 / 切片数）→ 展开一篇，行内 textarea 改一段切片文字 → 保存 → 点顶部「重建索引」→ 成功 toast → 切回聊天问同一问题，回答按新文本走。
- 台词：「知识库不是只读的。侧边栏点『知识库』进 /kb，40 篇文档按切片列出来，标题、分类、切片数一目了然。展开一篇，行内直接改一段文字，保存时这一块重新嵌入，检索缓存同时失效。再点顶部『重建索引』，BM25 和向量索引一起刷新。回到聊天问同一个问题，回答立刻按新内容来。改知识、重建、验证，一分钟内走完，不求后台、不等工单。」
- 时长：60s
- 对应文件：app/kb/page.tsx、backend/app/api_kb.py、backend/app/rag/retrieve.py、backend/app/rag/pipeline.py

### 7. 会话持久化与模式徽章

- 画面：左栏会话列表，RAG / Agent 徽章分色；给会话改名、两步确认删除；刷新整页 → 会话和消息原样回来，意图徽章还在。
- 台词：「会话全部存在本地 SQLite，刷新页面不丢。新建、改名、删除都有两步确认，手滑删不掉。每个会话带 RAG 或 Agent 徽章，隔几天回来，一眼知道当时用的哪种模式。意图徽章跟着消息一起持久化，老会话没这个字段，照样正常打开。」
- 时长：30s
- 对应文件：backend/app/store.py、components/Sidebar.tsx、lib/useSessions.ts、app/api/v1/[...path]/route.ts

### 8. Agent 步骤卡片

- 画面：放大一张步骤卡片：图标 + 工具中文名（知识库检索 / 数据查询 / 文案生成 / 合规检查）+ 参数摘要 + 「运行中 / ✓ 完成」状态；点「详情」展开完整返回结果，再点收起。
- 台词：「步骤卡片是 Agent 的透明窗：调了哪个工具、带了什么参数、跑完没有，全在卡上。点『详情』能看到工具原样返回的数据，再点收起。哪一步出了问题不用猜，翻卡片就知道。」
- 时长：30s
- 对应文件：components/AgentSteps.tsx、lib/agentClient.ts、backend/app/agent/loop.py

### 9. 点引用角标，弹出来源卡片

- 画面：回到镜头 1 的回答，点 [1] → 右下角弹出「知识库来源」卡片：标题、分类、原文片段 → 点遮罩关闭。补拍一条 Agent 回答的角标，展示「未找到来源」的兜底提示。
- 台词：「回答里的角标都能点。点开右下角弹出来源卡片，标题、分类、命中的原文片段都在上面，哪句话有出处，当场核对。要是来源对不上，卡片会直说没找到，不拿一个假链接糊弄你。」
- 时长：30s
- 对应文件：components/CitationCard.tsx、components/MarkdownText.tsx、app/api/v1/[...path]/route.ts（/v1/rag/search 溯源）

## 三、技术架构（~1.5 min，100s）

### 10. 分层架构图

- 画面：分层图逐行浮现（ASCII 素材见本镜下方），高亮「AI 能力唯一接入层」一行。
- 台词：「最后看架构。前端 Next.js 只负责交互，问答、Agent、检索、视觉这些 AI 能力全部收在 FastAPI 一层。密钥只存在 Python 端，浏览器永远碰不到模型 API。这既是比赛规则，也是安全底线。」
- 时长：35s
- 对应文件：backend/app/main.py、README.md（架构图）

分层图（画面用 ASCII 素材）：

```
浏览器 Next.js（流式对话 · 步骤卡片 · 引用角标[1] · 语音/图片）
 │   同源代理 /api/v1/* 与 /api/chat · /api/agent · /api/vision
 ▼
FastAPI  backend/app/          ← AI 能力唯一接入层（比赛规则要求）
 ├── api/routes     /v1/chat/completions · /v1/agent/chat · /v1/intent · /v1/kb/*
 ├── agent/         手写 ReAct 循环 + 工具注册表（7 个工具，最多 5 步）
 ├── rag/           jieba BM25 + 向量 RRF 融合检索 · LanceDB · fastembed
 └── mcp_server/    独立进程（stdio），复用同一套工具
 ▼
外部: DeepSeek API · GLM-4V（可选）
```

### 11. 四个关键决策

- 画面：四张字卡依次切换，每张配一行文件名。
- 台词：「四个关键决策。Agent 循环手写，不引 LangChain，最多五步，行为可测可控。检索是 BM25 加向量的混合召回，RRF 融合排序，词面和语义都照顾到。数据接入做成 Provider 插件，换真实店铺只改一个类、一个环境变量。前端请求全走同源 /api/v1/* 代理转发，不直连后端端口。」
- 时长：35s
- 对应文件：backend/app/agent/loop.py、backend/app/rag/retrieve.py、backend/app/agent/data_provider.py、app/api/v1/[...path]/route.ts

### 12. 质量验收数字 + 如实标注 + 收尾

- 画面：三张数字大卡依次定格：检索自测 90%、开/关 RAG 评测 27/30、e2e API 测试 12/12；底部常驻字条「本地模拟数据，未接平台真实授权」；最后回到首页定版。
- 台词：「质量用数字说话：检索自测 90%，开/关 RAG 对比评测 27/30，端到端 API 测试 12 条断言全过。这里如实说明，演示跑的是本地模拟数据，未接平台真实授权；要接真实店铺，实现 Provider 契约就行。店智 Copilot，会查数、会引用、会思考。」
- 时长：30s
- 对应文件：backend/app/rag/selftest.py、backend/app/rag/eval_v2.py、p5_api_test.py（全链路断言）、README.md
