# 店智 Copilot 演示视频脚本（故事线 · 总时长 ~7 min）

> **开场设定**：小美是一家淘宝女装店的运营，早上 9 点打开店智 Copilot。镜头跟拍她这一天：早上答规则、查退款、给客户退 80 元，顺手备好上新文案；第二天复盘 Agent 是怎么想的、把过时规则改掉、翻回上次的排查现场。
> 每镜三段起手：**触发**（客户问题或业务麻烦）→ **Agent 动作**（它做了什么）→ **结果**（小美拿到了什么）。不是功能点名，是活儿怎么干完的。
> **总时长 410s ≈ 7 分钟**（要求区间 5-8 分钟）。
> 分段：一、一个运营的早晨 200s（效果演示）｜二、发现问题 110s（功能细节）｜三、架构与收尾 100s（技术架构）。
> 每镜栏位：触发 / Agent 动作 / 结果 / 画面 / 台词 / 时长 / 对应文件。
> 全片如实标注：演示跑的是**本地模拟数据**，未接平台真实授权。

## 一、一个运营的早晨（200s · 效果演示）

### 1. 开场：客户问「DSR 评分怎么算」

- 触发：昨晚有客户在旺旺里追问 DSR 评分的计算规则。规则问题凭感觉答要出事，小美早上第一件事就是弄清楚。
- Agent 动作：她把问题原样打进输入框，RAG 从 43 篇知识库文档里检索相关内容，流式生成回答，句尾挂 [1][2] 角标。
- 结果：哪句话来自哪篇文档一眼对得上，回答可以直接转给客户。碰到知识库没覆盖的，它直说没覆盖，不瞎编。
- 画面：打开 `/chat`。全局左导航（工作台 / 对话 / 数据 / 知识库）常驻，会话栏为空，右侧聊天窗口。输入「DSR 评分到底怎么算的？」，回答流式输出，句尾出现 [1][2] 角标。鼠标划过角标停一下。
- 台词：「早上九点，小美打开店智 Copilot。她是一家淘宝女装店的运营，昨晚客户追问：DSR 评分到底怎么算？她把问题原样打进来，系统从 43 篇知识库文档里检索出相关内容，流式生成回答，句尾挂着 [1][2] 角标。鼠标划过角标停一下，哪句话来自哪篇文档，一眼对得上。碰到知识库没覆盖的，它会直说没覆盖，不瞎编。卖家最怕 AI 张口就来，这里每句话都有出处。」
- 时长：45s
- 对应文件：app/chat/page.tsx、components/ChatWindow.tsx、components/MarkdownText.tsx、backend/app/rag/retrieve.py

### 2. 意图分流：客户催退款，一句「查退款进度」自动切 Agent

- 触发：客户紧接着追问「我那笔退款到哪一步了」。订单页一页页翻太慢，小美想直接问出来。
- Agent 动作：她输入「最近退款进度怎么样」。发送瞬间系统先做意图分类，气泡上方亮出 chip「意图：数据查询 · 路由 → Agent 工具 · 已按意图切换」，模式徽章从 RAG 自动跳成 Agent。
- 结果：该查数的去查数，该翻资料的翻资料，模式不用用户挑。对照补拍：问「DSR 是什么」，chip 显示知识问答、走检索，模式留在 RAG。
- 画面：输入「最近退款进度怎么样」→ chip 弹出、模式徽章切换、回答改由工具查询给出。切第二个问题「DSR 是什么」做对照，chip 与模式徽章留在 RAG。
- 台词：「客户催退款了。小美打『最近退款进度怎么样』，气泡上方直接亮徽章：意图：数据查询 · 路由 → Agent 工具 · 已按意图切换，模式徽章从 RAG 自己跳成 Agent。换回『DSR 是什么』，徽章写知识问答、走检索，模式留在 RAG。同一个输入框，该查数的去查数，该翻资料的翻资料，用户不用懂这些区别。」
- 时长：35s
- 对应文件：backend/app/agent/intent.py、backend/app/api_intent.py、lib/intentClient.ts、components/IntentChip.tsx、components/ChatWindow.tsx

### 3. Agent 查出退款进度，直接给建议

- 触发：退款单散在各处，小美今天得先弄清该盯哪几笔，不然下午全耗在翻单子上。
- Agent 动作：手写 ReAct 循环里模型自己决定调什么工具、调几次。order_lookup 拉退款数据，步骤卡片逐张出现（🔧 order_lookup → ✓ 完成），点「详情」展开返回 JSON，整条推理链一眼可追。
- 结果：三张表（退款中 / 被拒 / 已完成）加下一步建议：优先处理退款中那两笔，退货退款要盯物流。
- 画面：步骤卡片逐张出现 → 点「详情」展开 JSON → 收起 → 流式输出三张表格 + 建议清单。
- 台词：「Agent 跑的是手写 ReAct 循环，调什么工具、调几次，模型自己决定。这轮它拉出退款数据，步骤卡片一张张落下来，点『详情』，工具返回的 JSON 原样摊开。最后整理成三张表：两笔退款中、两笔被拒、两笔已完成。底下直接给建议：优先处理退款中那两笔，退货退款要盯物流。先查数、再分析、后建议，跟人类运营一个路子，而且每一步都摊开给你看。」
- 时长：40s
- 对应文件：backend/app/agent/loop.py、backend/app/agent/tools/__init__.py、components/AgentSteps.tsx、lib/agentRun.ts

### 4. 退款两段式：「这单退 80 元」，弹窗确认才动手

- 触发：有单退货谈妥了，小美拍板给 SO20261027004 退 80 元。真金白银的操作，误点了要跟客户扯皮。
- Agent 动作：refund_flow 第一段只校验：订单在不在、付没付过、金额超没超、过没过售后期。全过了才发一张 10 分钟有效的一次性确认令牌，弹出退款确认弹窗，然后停下来等。
- 结果：小美核对完订单、商品、退款金额、退款后剩余，点「确认退款」才执行第二段，回执带售后单号、状态、时间。补拍反例：金额填 418 元，后端直接回「退款金额 418.0 超过实付金额 199.0」。
- 画面：对话里说「SO20261027004 这单退 80 元，帮我处理」→ 校验通过 → 弹出退款确认弹窗（订单号 / 商品 / 买家 / 金额 / 退款后剩余）→ 点「确认退款」→ 回执。补拍金额违规被拦的反例。
- 台词：「SO20261027004 这单退 80 元，帮我处理。退款是敏感操作，做成两段式。第一轮只校验：订单在不在、付没付过、金额超没超、过没过售后期。全过了才发一张 10 分钟有效的确认令牌，弹出退款确认弹窗，订单、商品、退款金额、退款后剩余摆在上面，然后停下来等。小美点『确认退款』，第二段才真正执行，回执带售后单号、状态和时间。就算重复执行，也只回一句已退款。金额填错更简单，后端一句『退款金额 418.0 超过实付金额 199.0』直接拦下。校验规则全在后端，模型说了不算。」
- 时长：50s
- 对应文件：components/RefundDialog.tsx、backend/app/api_refund.py、backend/app/agent/__init__.py（refund_flow）、backend/app/agent/data_provider.py

### 5. 顺手备上新：图生文案 + 语音

- 触发：下午要上新一款连衣裙，白底图有了，详情页文案还没影。小美手里还接着别的活。
- Agent 动作：点 🖼️ 上传商品白底图，视觉模型返回标题 / 卖点 / 描述卡片并自动填入输入框；再点 🎤 说「帮我看看退款率太高怎么办」，语音转文字上屏。
- 结果：文案改两个字就能发详情页；手上不停活，说话也能继续提问。
- 画面：上传商品图 → 标题 / 卖点 / 描述卡片 → 自动填入输入框 → 手动改两个字。点 🎤 说话 → 文字上屏 → 发送。
- 台词：「上午顺手把下午上新的准备做了。拍张商品白底图，点 🖼️ 上传，视觉模型直接给出标题、卖点和描述，自动填进输入框，她改两个字就能发详情页。手边还在打包，不想打字就点 🎤，说一句『帮我看看退款率太高怎么办』，文字上屏接着问。」
- 时长：30s
- 对应文件：app/api/vision/route.ts、components/ChatWindow.tsx（Web Speech API）

## 二、发现问题（110s · 功能细节）

### 6. Agent 推理过程：工具链、耗时、每步理由（面板特写）

- 触发：第二天老板问：上午那条「优先处理退款中两笔」的建议，依据是什么？小美得给出交代，不能说「AI 说的」。
- Agent 动作：她点开那轮回答的 Agent 推理过程面板。整条工具链摊开：order_lookup → data_query → refund_flow，每一步标着耗时、调用理由和参数摘要，点「详情」看工具原样的 JSON 返回。
- 结果：为什么先查订单（问题里带单号）、为什么再调数据查询（要算退款率才好下结论），逐步说得清。哪步出问题、哪步慢了，翻卡片就定位，不用事后猜。
- 画面：放大步骤卡片。第一张 order_lookup：参数摘要 + 耗时 + 「✓ 完成」，点「详情」展开完整 JSON。切到第二张 data_query、第三张 refund_flow（validate → execute），展示三步调用链和各自的耗时与理由。再点收起。
- 台词：「老板问依据是什么。小美点开回答上方的推理过程面板，整条工具链摊在眼前：order_lookup 查订单，data_query 拉经营快照，refund_flow 校验退款。每一步都标着耗时和调用理由：为什么先查订单？问题里带单号。为什么要调数据查询？要算退款率才好下结论。参数摘要一行看全，点『详情』是工具原样的 JSON 返回。出了问题不用猜，翻卡片就知道卡在哪一步，比事后翻日志快多了。」
- 时长：40s
- 对应文件：components/AgentSteps.tsx、lib/agentRun.ts、backend/app/agent/loop.py

### 7. 知识过时了：改一块，马上生效

- 触发：复盘时小美发现知识库里写着「退款率超 10% 会被处罚」，最新口径其实是 8%。照旧回答会误导运营决策。
- Agent 动作：侧边栏进 /kb，找到「退款率过高的后果与控制」，行内把 10% 改成 8%。保存时这一块重新嵌入、检索缓存失效，再点「重建索引」刷新 BM25 和向量索引。
- 结果：切回聊天重问「退款率多少会被处罚」，答案立刻变成 8%。改知识、重建、验证，一分钟内走完，不求后台、不等工单。
- 画面：/kb 页面 43 篇文档列表 → 展开目标文档 → 行内改「10%」为「8%」→ 保存（按钮变灰，状态标「与索引一致」）→ 重建索引成功 toast（含耗时）→ 回聊天重问，答案变 8%。
- 台词：「排查时她发现一条规则过时了：写着退款率超 10% 会被处罚，最新口径是 8%。知识库不是只读的。进 /kb 找到那篇，行内直接改，保存时这一块重新嵌入，检索缓存同时失效。点重建索引，BM25 和向量索引一起刷新。回来重问同一个问题，答案立刻按新内容来。改知识、重建、验证，一分钟内走完。」
- 时长：40s
- 对应文件：app/kb/page.tsx、backend/app/api_kb.py、backend/app/rag/retrieve.py、backend/app/rag/pipeline.py

### 8. 隔几天回来：排查现场还在

- 触发：又过了几天，客户那笔纠纷的处理要接着上次的排查继续。小美早忘了当时查到哪一步。
- Agent 动作：刷新整页，会话和消息原样回来，意图徽章还在。左栏每个会话带 RAG / Agent 徽章分色，改名、两步确认删除都在手边。回答里的引用角标可点。
- 结果：点 [1] 弹出来源卡片（标题 / 分类 / 原文片段），哪句话有出处当场核对。排查进度不丢，接着上次往下走。
- 画面：左栏会话列表 → 刷新整页（内容原样回来）→ 点引用角标 [1] → 右下角来源卡片弹出 → 关闭。
- 台词：「隔几天回来，会话还在。全存在本地 SQLite，刷新不丢。每个会话带 RAG 或 Agent 徽章，一眼知道当时用的哪种模式。回答里的角标都能点，右下角弹出来源卡片，标题、分类、原文片段，哪句话有出处当场核对。上次查到哪、引了哪篇，接上就走。」
- 时长：30s
- 对应文件：backend/app/store.py、components/Sidebar.tsx、components/CitationCard.tsx、lib/useSessions.ts

## 三、架构与收尾（100s · 技术架构）

### 9. 分层架构图

- 画面：分层图逐行浮现（ASCII 素材见下方），高亮「AI 能力唯一接入层」一行。
- 台词：「这一天的活儿背后是这套架构。前端 Next.js 只负责交互，问答、Agent、检索、视觉这些 AI 能力全部收在 FastAPI 一层。密钥只存在 Python 端，浏览器永远碰不到模型 API。这既是比赛规则，也是安全底线。」
- 时长：35s
- 对应文件：backend/app/main.py、README.md（架构图）

分层图（画面用 ASCII 素材）：

```
浏览器 Next.js（流式对话 · 步骤卡片 · 引用角标[1] · 语音/图片）
 │   同源代理 /api/v1/* 与 /api/chat · /api/agent · /api/vision
 ▼
FastAPI  backend/app/          ← AI 能力唯一接入层（比赛规则要求）
 ├── api/routes     /v1/chat/completions · /v1/agent/chat · /v1/intent · /v1/kb/*
 ├── agent/         手写 ReAct 循环 + 工具注册表（10 个工具，最多 5 步）
 ├── rag/           jieba BM25 + 向量 RRF 融合检索 · LanceDB · fastembed
 └── mcp_server/    独立进程（stdio），复用同一套工具
 ▼
外部: DeepSeek API · GLM-4V（可选）
```

## 与同类系统对比定位

| 维度 | 同类客服系统 | 店智 Copilot |
|---|---|---|
| 叙事方式 | 功能清单巡礼（分段介绍） | **一个运营的一天**故事线 |
| 意图分流 | 描述"智能路由" | chip 可视化 + 自动切换 + 实时对比 |
| 退款操作 | "业务校验和确认流程" | **两段式可跑**：校验→令牌→弹窗确认→幂等回执 |
| Agent 透明度 | 事后查路由记录/日志 | **推理过程面板**：工具链 + 耗时 + 每步理由 + 原样 JSON |
| 知识来源 | "展示知识来源" | **[1][2] 角标 + 点击弹出原文卡片** |
| 知识库管理 | 版本发布/生效时间/回滚 | **编辑即生效**（保存→重嵌入→检索失效，一分钟） |
| 人工客服 | 转人工/接管/接待范围 | 不做（聚焦 AI 能力深度） |
| 运营后台 | 全量 CRUD（客户/商品/支付/物流…） | 不做（聚焦智能体，不做 ERP） |
