# 店智 Copilot 演示视频脚本（直接服务顾客 · 总时长 ~7 分 50 秒）

> **产品定位**：直接服务顾客的电商智能客服 Agent。售前帮顾客选品、查库存；售后帮顾客查订单、诊断退款和退货受阻、拦截在途物流、处理投诉。商品知识与售后规则在后台维护，保证回答有据。
> **叙事主线**：一位顾客发现收货地址填错、包裹已发货，通过两轮确认完成物流拦截；随后看退款受阻诊断与投诉处理；后半段看知识库改完怎么让顾客下一句就得到新答案。每个镜头先说顾客遇到什么，再看 Agent 调了哪些工具，最后看事情推进到哪一步。
> **技术看点**：LangGraph 6 节点多 Agent（Router / 澄清 / 售前 / 售后 / 投诉 / 终审）、10 个工具注册表（7 个客服工具 + 3 个运营向，MCP 暴露 4 个）、退款只读预检、改址/拦截/退换两段式门控、RAG 引用溯源。
> **总时长 470s ≈ 7 分 50 秒**（要求 5–8 分钟）。分段：零、开场 20s｜一、顾客办事 260s｜二、知识供给与过程透明 110s｜三、架构与收尾 80s。
> **如实标注**：演示使用本地 20 单种子数据，未接淘宝/拼多多真实授权；退款只做只读预检，物流拦截只作用于种子库。

## 零、开场（20s）

- 画面：标题字卡停 2 秒，切到 `/chat` 空状态；镜头缓慢掠过左侧三个入口「客服对话 / 知识库后台 / 系统概览」。
- 台词：「店智 Copilot 是一个直接服务顾客的电商客服 Agent。顾客在聊天框里选商品、查订单、处理退款受阻和投诉，Agent 当场把事推进；商品知识和售后规则在后台维护，保证每句回答都有据。下面跟着一位顾客，看她怎么把三件事办完。」

## 一、顾客办事（260s）

### 1. 顾客入口：三条常用任务直接开跑（25s）

- 触发：顾客打开客服页，不知道从哪问起。
- 画面：`/chat` 空状态。标题「不只是聊天，是能把事办完」；桌面双栏：左栏「三条高频任务」三行（拦截物流 / 售后异常 / 投诉建单，每行问题、预期结果与「开始」按钮）+ 4 张能力卡（售前推荐 / 拦截物流 / 退款受阻 / 投诉升级，每张卡下一行场景说明），右栏「四步把事办完」说明卡（先弄明白你要办什么 / 查真实数据 / 有据才回答 / 给出结果和下一步）与「查看系统概览」入口；左侧三入口：客服对话 / 知识库后台 / 系统概览。
- 台词：「顾客打开客服页，不用先想清楚怎么提问。首页把三条最常办的事摆出来：拦截物流、售后异常、投诉建单，点『开始』就能跑；下面的能力卡里还有退款受阻和售前推荐。右边四步写清楚它怎么办事：先弄明白、查真实数据、有据才回答、给出结果和下一步。」
- 对应文件：`components/DemoGuide.tsx`、`components/ScenarioCards.tsx`

### 2. 拦截物流：首轮校验，手输确认后执行（55s）

- 触发：顾客发现收货地址填错，包裹已经发货，想拦下来。
- 画面：点路线「拦截物流」右侧「开始」，问题 `SO20261027007 地址填错了，已经发货了，能帮我拦截吗？` 直接发送。回答先给出订单信息：周\*、纯棉基础款T恤 + 桌面收纳盒、实付 ¥129.8、已发货、顺丰速运 `SF7392846152738`、原地址；回答中提示输入「确认拦截」。右侧「订单详情」抽屉同步展开，显示商品、金额、已发货状态与时间线（下单/支付/发货）；订单详情卡不展示承运商、运单号和地址，物流信息以回答文案为准。
- Agent 动作：Router 判为售后，交给售后 Agent；售后 Agent 调 `order_lookup(order_id=SO20261027007)` 查订单，再调 `intercept_logistics` 做拦截校验。首轮只校验、返回 `needs_confirm`，不执行；数据库仍是 `shipped`。
- 二次确认：顾客在输入框手动输入 `确认拦截`；前端带完整历史再次请求，Agent 重新校验令牌后调用 `intercept_logistics` 执行，状态变为 `intercepted`，回答给出拦截成功回执。不要点任何确认按钮，演示路线不会自动发第二轮。
- 画面补充：执行成功后，右侧订单抽屉通过刷新键重拉，徽章变为「已拦截」，时间线补上发货与物流拦截节点。
- 台词：「顾客说地址填错了，包裹已经发了，能不能拦。Router 判为售后，售后 Agent 先查订单，再调 intercept_logistics 做拦截校验。第一轮只校验、不执行，回答把订单、顺丰运单号和原地址摊开，请顾客确认。右边订单卡同步展开。顾客手动输入『确认拦截』，Agent 重新校验令牌后执行，状态变成已拦截。敏感操作必须客户确认，模型不能自己动。」
- 对应文件：`backend/app/agent/graph.py`、`backend/app/agent/data_provider.py`、`components/ChatWindow.tsx`、`components/OrderDetailCard.tsx`

### 3. 多 Agent 面板特写：路由、handoff、工具轨迹、终审（45s）

- 触发：顾客（和评审）想知道「这真是多 Agent，还是一个大模型在调工具？」
- 画面：点开回答上方的「多 Agent 处理过程」面板并放大：
  1. 顶部徽章「售后 Agent 接手」+ 4 个专家花名册（售前 / 售后 / 投诉 / 澄清，售后高亮，其余灰显，右侧写「按意图选 1 个」）；
  2. Router Agent 一行：`置信度 0.97 · 情绪 neutral`，下一行 `意图 aftersales`；
  3. `↳ Router → 售后 Agent（handoff）`；
  4. 售后 Agent 的工具轨迹：首轮 assistant 消息展示 `order_lookup(order_id=SO20261027007)` 与 `intercept_logistics`（validate，`needs_confirm`）；第二轮 assistant 消息展示 `intercept_logistics`（validate 后 execute，`state=intercepted`）。
  5. Review Agent 一行：`通过 · 证据 N 条 · 引用 0 条`。
- 台词：「这块面板每一行都有实际内容。四个专家常驻，这一轮 Router 选了售后，其余三个灰掉；handoff 这一行表示路由把会话交给售后。售后调了哪些工具、返回哪些字段，面板原样列出来；最后 Review 做证据校验，没证据就拒答。单轮只命中一个专家，但路由、工具证据和终审裁决都能看见。」
- 对应文件：`components/ThoughtChain.tsx`、`backend/app/agent/graph.py`

### 4. 退款受阻：先查状态，再给政策与申诉路径（55s）

- 触发：顾客的退款申请被商家拒绝，不知道下一步。
- 画面：新建会话，点路线「售后异常」的「开始」，发送 `SO20261027011 的退款被拒了，为什么？我该怎么办？`。点开「多 Agent 处理过程」面板，显示售后 Agent 接手、`order_lookup(order_id=SO20261027011)`，订单卡显示蒋\*、LED化妆镜带灯 ×1、¥119、已收货；随后 `kb_search` 命中退款/售后政策。回答说明售后单状态「被拒」、可能原因、需要补充的证据，以及订单页重新申请、申诉或升级投诉的路径。
- Agent 动作：退款不执行，只做资格预检与受阻诊断；正常退款引导客户去平台订单页自助申请，Agent 负责解释规则、查状态、整理证据和升级建议。
- 台词：「退款这一步，Agent 不越权代办。平台订单页已经支持顾客自己申请，Agent 负责查订单和售后单、解释退款政策，再告诉她为什么被拒、还缺什么、下一步是重新申请还是升级投诉。退款动作留在平台，Agent 把规则和路径讲清楚。」
- 对应文件：`backend/app/agent/graph.py`、`backend/app/agent/__init__.py`（`refund_flow` 只读预检）

### 5. 售前推荐：按预算查商品与库存（35s）

- 触发：顾客想给父母买礼物，预算 200 元以内。
- 画面：新建会话，点能力卡「售前推荐」，发送 `200 元以内送父母的礼物，有什么推荐？`。点开「多 Agent 处理过程」面板，显示「售前 Agent 接手」、售前高亮，工具轨迹 `product_lookup(keyword=...)`，回答给出商品名、价格、库存，并追问使用对象与容量偏好。
- 台词：「售前走另一条路。Router 选售前 Agent，它调 product_lookup 查价格和库存，回答里给出具体商品、金额和剩余库存；信息不够时先追问，不硬推。」
- 对应文件：`backend/app/agent/graph.py`、`components/ScenarioCards.tsx`

### 6. 投诉建单：情绪识别 + 工单 + 处理方案（45s）

- 触发：顾客等了一周没到，情绪上来了。
- 画面：新建会话，点路线「投诉建单」的「开始」，发送 `等了一周还没到，太失望了，我要投诉！`。用户消息上方意图 chip 显示「意图：投诉升级 · 路由 → Agent 工具」，下方一枚「愤怒」情绪徽章。点开「多 Agent 处理过程」面板，显示「投诉 Agent 接手」、投诉高亮、Router 置信度 0.97 / 情绪angry、handoff、`类别:物流配送 紧急度:high`、`已生成工单 TK-…`，Review 裁决「工单已受理 · 已转人工」。页头出现「投诉处理方案」按钮。
- 二次动作：点页头「投诉处理方案」，在弹窗里填一句诉求（如「物流一周未更新，顾客要求赔偿」）并点「生成处理方案」；弹窗关闭，对话区出现「投诉处理方案」卡片，分三块：情况摘要、建议动作、可复制话术。
- 台词：「Router 除了判意图，还会看情绪，这一轮是 angry。投诉 Agent 把对话整理成工单：物流配送、紧急度 high，生成 TK 工单号，终审用安抚的语气告诉顾客已经受理。页头的『投诉处理方案』再补一份材料：情况摘要、建议动作和可复制话术，Agent 直接据此回复顾客，把安抚和后续处理讲清楚。」
- 对应文件：`backend/app/agent/graph.py`、`components/EscalateDialog.tsx`、`backend/app/api_escalation.py`

### 7. 知识库编辑即生效（45s）

- 画面：切到 `/kb`，43 篇文档列表。打开《退款率过高的后果与控制》，把「一般建议将退款率控制在类目均值以内」改成「一般建议将退款率控制在 8% 以内」，点保存，状态回到「与索引一致」。回 `/chat` 问 `退款率控制在多少比较安全？`，回答给出 8%，句末带 `[1]`。

- 对应文件：`app/kb/page.tsx`、`backend/app/rag/pipeline.py`、`backend/app/rag/retrieve.py`

### 8. 刷新不丢：会话与引用都能回查（30s）

- 触发：顾客隔天回来继续问。
- 画面：刷新整页，左侧会话列表与消息原样恢复；点回答里的 `[1]`，右下弹出引用卡片，显示标题、分类、原文片段。
- 台词：「会话存在本地 SQLite，刷新不丢；每个会话带 AGENT 标记。回答里的角标可以点开来源卡片，哪句话来自哪篇文档，当场能核对。」

### 9. 终审与拒答：没证据就不编（35s）

- 触发：评审问「模型胡说怎么办？」
- 画面：回到拦截物流会话，指 Review 行的「通过 · 证据 N 条」；再展示无工具、无引用的追问场景，Review 显示「追问放行（无工具）」或「拒答（无证据）」。
- 台词：「每个专家的输出都要过终审：有工具证据才放行，有引用才允许带角标；没证据就拒答或追问，不硬编。工具异常也不会把报错直接甩给顾客，会转成能看懂的提示，让模型换条路。」
- 对应文件：`backend/app/agent/graph.py`（review 节点）

## 三、架构与收尾（80s）

### 10. 分层架构：AI 能力只在 FastAPI 一层（35s）

- 画面：分层图逐行浮现，高亮「AI 能力唯一接入层」。
- 台词：「前端 Next.js 只负责交互，问答、Agent、检索、视觉都收在 FastAPI 这一层。浏览器不直连模型，密钥只在 Python 端；同源代理把 `/api/*` 转到后端，接入规范和安全都照顾到。」
- 对应文件：`backend/app/main.py`、`app/api/v1/[...path]/route.ts`

```
浏览器 Next.js 16（流式对话 · 多 Agent 面板 · 引用角标 · 语音/图片）
 │  同源代理 /api/agent · /api/vision · /api/v1/*
 ▼
FastAPI  backend/app/          ← AI 能力唯一接入层
 ├── LangGraph 6 节点：Router / Clarify / Presales / Aftersales / Escalation / Review
 ├── 工具注册表 10 个（7 个客服 + 3 个运营向）· MCP 独立进程暴露 4 个
 ├── RAG：jieba BM25 + fastembed + LanceDB（43 篇语料）
 └── SqliteSaver 会话检查点 · DataProvider 取数（sqlite / mock 可切）
 ▼
外部：DeepSeek API · GLM-4V（可选）
```

### 11. 关键决策：为什么这样搭（25s）

- 画面：四张字卡依次切换。
- 台词：「四个决策。第一，编排用 LangGraph。多 Agent 路由、检查点、人工确认都能直接表达，比手写循环省事。第二，检索走 BM25 加向量的混合召回，RRF 融合。第三，数据接入做成 Provider 插件，换真实店铺只改一个类和一个环境变量。第四，退款只读预检，改址、拦截、退换统一走 validate → 确认 → execute，模型不直接动钱。」
- 对应文件：`backend/app/agent/graph.py`、`backend/app/rag/retrieve.py`、`backend/app/agent/data_provider.py`

### 12. 质量数字 + 收尾（20s）

- 画面：数字卡依次定格：43 篇语料 / 12 段场景 / 20 单种子；检索自测 90%（9/10）；RAG 评测 v2 29/30（无 RAG 30/30，增量在私有规则与引用）；冒烟 10/10；tsc / eslint / build 全绿。底部常驻字条「本地模拟数据，未接平台真实授权」。
- 台词：「最后看几组质量数据：检索自测 90%，RAG 评测 29 比 30；无 RAG 在通用常识题上也很强，RAG 的增量主要在平台私有规则、知识库口径和引用可溯源。冒烟 10/10，前端构建和类型检查全绿。演示跑的是本地种子数据，未接平台真实授权；要接真实店铺，实现 DataProvider 契约就行。店智 Copilot，直接服务顾客的电商智能客服 Agent：顾客在对话里把事办完，回答依据在后台随时更新。」
- 对应文件：`backend/app/rag/selftest.py`、`docs/rag-eval-v2.md`、`scripts/smoke.mjs`

## 与同类系统对比定位

| 维度 | 同类客服系统 | 店智 Copilot |
|---|---|---|
| 多 Agent | 宣传"智能路由"，界面只看到一次回答 | **4 专家花名册 + Router 意图 + handoff + 工具轨迹 + 终审裁决** |
| 办理能力 | 查询后跳工单/转人工 | **对话内完成改址/拦截/退换**，退款引导平台自助，办理类两段式门控 |
| 退款处理 | 后台表单或人工 | **平台订单页自助申请；Agent 查状态、讲规则、给申诉路径** |
| 过程透明 | 事后日志 | **面板逐轮留痕**：谁接手、调了什么、返回什么、终审是否放行 |
| 知识来源 | 展示来源列表 | **`[1]` 角标 + 点击弹出原文卡片** |
| 知识库后台管理 | 版本发布/回滚 | **编辑即生效**（保存→重嵌入→检索失效，一分钟） |
| 人工客服 | 转人工接管 | 投诉建单转人工，其余在对话内处理完 |
