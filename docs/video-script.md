# 店智 Copilot 演示视频脚本（故事线 · 总时长 ~7 min）

> **一条线**：运营小美的一天——早上查退款、确认退款、中午改知识库、下午复盘排查。
> 每个镜头有触发原因（为什么做）和落地结果（拿到了什么），不是功能点名。
> **总时长 420s ≈ 7 分钟**（要求区间 5-8 分钟）。
> 分段：一、一个运营的早晨 210s（3.5 min）｜二、运营的下午 110s（~2 min）｜三、技术架构 + 质量 100s（~1.5 min）
> 每镜四栏：画面 / 台词 / 时长 / 对应文件。

---

## 一、一个运营的早晨（210s）

### 1. 开场 + 客户问了个规则问题

- 画面：首页双栏布局。左栏会话列表为空，右栏聊天窗口。小美（旁白代入）收到客户消息"DSR 评分到底怎么算的？"，她把问题原样打进输入框。RAG 模式回答流式输出，句尾出现 [1][2] 角标。鼠标划过角标停一下。
- 台词：「早上九点，运营小美打开店智 Copilot。客户问了个规则问题——DSR 评分怎么算。她把问题原样打进来，系统从 43 篇知识库文档里检索出相关内容，流式生成回答，句尾带 [1][2] 角标。哪句话来自哪篇文档，一眼对得上。碰到知识库没覆盖的，它会直说没覆盖，不瞎编。卖家最怕 AI 张口就来，这里每句话都有出处。」
- 时长：45s
- 对应文件：app/page.tsx、components/ChatWindow.tsx、components/MarkdownText.tsx、backend/app/rag/retrieve.py

### 2. 意图分流：一句"查退款"自动切 Agent

- 画面：小美接着想看退款情况，输入「最近退款进度怎么样」。发送瞬间，气泡上方弹出小徽章「意图：数据查询 · 路由 → Agent 工具 · 已按意图切换」，模式徽章从 RAG 自动跳成 Agent，回答改由工具查询给出。补拍对照：问「DSR 是什么」，徽章显示「知识问答 → 检索」，模式留在 RAG。
- 叏词：「同一个输入框，模式不用你挑。发『最近退款进度怎么样』，系统先做意图分类，气泡上直接亮徽章：数据查询，路由到 Agent 工具，模式自动切了过去。换回『DSR 是什么』，徽章写知识问答、走检索，模式留在 RAG。该查数的去查数，该翻资料的翻资料，用户不用懂这些区别。」
- 时长：35s
- 对应文件：backend/app/agent/intent.py、backend/app/api_intent.py、lib/intentClient.ts、components/ChatWindow.tsx

### 3. Agent 查出退款进度 + 给建议

- 画面：Agent 自动调用 `order_lookup`，步骤卡片逐张出现：🔧 order_lookup →「✓ 完成」→ 点「详情」展开返回 JSON。两张卡片后流式输出退款进度汇总：三张表格（退款中 / 被拒 / 已完成）+ 建议下一步（优先处理退款中 / 复查被拒单 / 关注退款率）。
- 台词：「Agent 跑的是手写 ReAct 循环，调什么工具、调几次，模型自己决定。这里它拉出退款数据，整理成三张表：两笔退款中、两笔被拒、两笔已完成。底下直接给建议：优先处理退款中那两笔，退货退款要跟踪物流。先查数、再分析、后建议，跟人类运营一个路子，而且每一步都摊开给你看。」
- 时长：40s
- 对应文件：backend/app/agent/loop.py、backend/app/agent/tools/__init__.py、components/AgentSteps.tsx、lib/agentRun.ts

### 4. 退款两段式确认（故事高潮）

- 画面：小美指着其中一单说「SO20261025016 这单退 80 元，帮我处理」。第一轮：Agent 调 refund_flow 校验，回复预览（订单号 / 金额 / 商品 / 已退金额）并问「确认退款吗？」，此时**停下来等**。第二轮：小美输入「确认」，返回执行回执（含售后单号、状态、时间）。补拍反例：金额填 418 元，返回「退款金额 418.0 超过实付金额 159.0」。
- 台词：「退款是敏感操作，做成两段式。第一轮只校验：订单在不在、付没付过、金额超没超、过没过售后期。全过了才发一个 10 分钟有效的确认令牌，把预览复述给你，然后停下来等。你说『确认』它才真正执行，说『不用』就什么都不动。就算重复执行，也只会回你一句已退款。校验规则全在后端，模型说了不算。」
- 时长：50s
- 对应文件：backend/app/agent/tools/__init__.py（refund_flow）、backend/app/agent/data_provider.py、backend/app/agent/seed_store.py

### 5. 顺手处理：图生文案 + 语音

- 画面：小美拍了张商品白底图，点 🖼️ 上传 → 返回标题 / 卖点 / 描述卡片 → 自动填入输入框，改两个字。再点 🎤 说「帮我看看退款率太高怎么办」→ 文字上屏 → 发送。
- 台词：「顺手拍张商品图，视觉模型直接给出标题、卖点和描述，改一改就能发。不想打字就点麦克风，说话也能提问。」
- 时长：25s
- 对应文件：app/api/vision/route.ts、components/ChatWindow.tsx（Web Speech API）

## 二、运营的下午（110s）

### 6. 发现知识过时 → 改一块，马上生效

- 画面：小美发现一条规则说"退款率超 10% 会被处罚"，但最新口径是"超 8%"。侧边栏点「知识库」→ /kb 页面，43 篇文档列表 → 展开「退款率过高的后果与控制」→ 行内改"10%"为"8%" → 保存（按钮变灰，状态标「与索引一致」）→ 点顶部「重建索引」→ 成功 toast → 切回聊天重问「退款率多少会被处罚」，回答变成"8%"。
- 台词：「知识库不是只读的。发现内容过时了，进 /kb 找到那篇，行内直接改。保存时这一块重新嵌入，检索缓存同时失效。点重建索引，BM25 和向量索引一起刷新。回来重问同一个问题，答案立刻按新内容来。改知识、重建、验证，一分钟内走完，不求后台、不等工单。」
- 时长：55s
- 对应文件：app/kb/page.tsx、backend/app/api_kb.py、backend/app/rag/retrieve.py、backend/app/rag/pipeline.py

### 7. 问题排查：Agent 每一步都透明

- 画面：回到镜头 3 的 Agent 回答，放大步骤卡片：🔧 order_lookup + 参数摘要 + 状态「✓ 完成」。点「详情」展开完整 JSON 返回（订单数据原样）。再点收起。切换到另一张卡片，展示工具调用链：order_lookup → refund_flow（validate）→ refund_flow（execute）。
- 台词：「出了问题不用猜。Agent 的步骤卡片是透明窗：调了哪个工具、带了什么参数、返回了什么数据，全在卡上。点『详情』看工具原样的 JSON，再点收起。哪一步出了问题，翻卡片就知道。这比事后翻日志快多了。」
- 时长：35s
- 对应文件：components/AgentSteps.tsx、lib/agentClient.ts、backend/app/agent/loop.py

### 8. 隔几天回来：会话还在

- 画面：左栏会话列表，RAG / Agent 徽章分色。给会话改名、两步确认删除。刷新整页 → 会话和消息原样回来，意图徽章还在。点引用角标 [1] → 右下角弹出来源卡片（标题 / 分类 / 原文片段）→ 关闭。
- 台词：「会话全存在本地 SQLite，刷新不丢。每个会话带 RAG 或 Agent 徽章，隔几天回来一眼知道当时用的哪种模式。回答里的角标都能点，弹出来源卡片，哪句话有出处当场核对。」
- 时长：30s
- 对应文件：backend/app/store.py、components/Sidebar.tsx、components/CitationCard.tsx、lib/useSessions.ts

## 三、技术架构 + 质量（100s）

### 9. 分层架构图

- 画面：分层图逐行浮现（ASCII 素材见下方），高亮「AI 能力唯一接入层」一行。
- 台词：「最后看架构。前端 Next.js 只负责交互，问答、Agent、检索、视觉这些 AI 能力全部收在 FastAPI 一层。密钥只存在 Python 端，浏览器永远碰不到模型 API。这既是比赛规则，也是安全底线。」
- 时长：35s
- 对应文件：backend/app/main.py、README.md（架构图）

分层图（画面用 ASCII 素材）：

```
浏览器 Next.js（流式对话 · 步骤卡片 · 引用角标[1] · 语音/图片）
 │   同源代理 /api/v1/* 与 /api/chat · /api/agent · /api/vision
 ▼
FastAPI  backend/app/          ← AI 能力唯一接入层（比赛规则要求）
 ├── api/routes     /v1/chat/completions · /v1/agent/chat · /v1/intent · /v1/kb/*
 ├── agent/         手写 ReAct 循环 + 工具注册表（7 个工具，最多 5 步）
 ├── rag/           jieba BM25 + 向量 RRF 融合检索 · LanceDB · fastembed
 └── mcp_server/    独立进程（stdio），复用同一套工具
 ▼
外部: DeepSeek API · GLM-4V（可选）
```

### 10. 四个关键决策

- 画面：四张字卡依次切换，每张配一行文件名。
- 台词：「四个关键决策。Agent 循环手写，不引 LangChain，最多五步，行为可测可控。检索是 BM25 加向量的混合召回，RRF 融合排序，词面和语义都照顾到。数据接入做成 Provider 插件，换真实店铺只改一个类、一个环境变量。前端请求全走同源代理，不直连后端端口。」
- 时长：30s
- 对应文件：backend/app/agent/loop.py、backend/app/rag/retrieve.py、backend/app/agent/data_provider.py、app/api/v1/[...path]/route.ts

### 11. 质量数字 + 如实标注 + 收尾

- 画面：三张数字大卡依次定格：检索自测 90%、开/关 RAG 评测 27/30、API 测试 23/23；底部常驻字条「本地模拟数据，未接平台真实授权」；最后回到首页定版。
- 台词：「质量用数字说话：检索自测 90%，开/关 RAG 对比评测 27/30，端到端 API 测试 23 条断言全过。这里如实说明，演示跑的是本地模拟数据，未接平台真实授权；要接真实店铺，实现 Provider 契约就行。店智 Copilot，会查数、会引用、会思考。」
- 时长：35s
- 对应文件：backend/app/rag/selftest.py、backend/app/rag/eval_v2.py、p5_api_test.py、README.md

## 与同类系统对比定位

| 维度 | 同类客服系统 | 店智 Copilot |
|---|---|---|
| 叙事方式 | 功能清单巡礼（分段介绍） | **一条运营的一天**故事线 |
| 意图分流 | 描述"智能路由" | chip 可视化 + 自动切换 + 实时对比 |
| 退款操作 | "业务校验和确认流程" | **两段式可跑**：校验→令牌→确认→幂等回执 |
| 知识来源 | "展示知识来源" | **[1][2] 角标 + 点击弹出原文卡片** |
| 知识库管理 | 版本发布/生效时间/回滚 | **编辑即生效**（保存→重嵌入→检索失效，一分钟） |
| 问题排查 | 事后查路由记录/日志 | **实时步骤卡片**：工具+参数+返回 JSON，点详情展开 |
| 人工客服 | 转人工/接管/接待范围 | 不做（聚焦 AI 能力深度） |
| 运营后台 | 全量 CRUD（客户/商品/支付/物流…） | 不做（聚焦智能体，不做 ERP） |
