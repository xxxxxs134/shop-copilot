# 店智 Copilot 演示视频脚本（顾客办事 + 商家维护 · 总时长 ~7 min）

> **产品定位**：面向客户的电商智能客服 Agent——售前选品、售后查单退款、投诉建单，全在一个对话框里办完。
> **叙事主线**：顾客小美遇到订单、退款、投诉三件事；后半段切到商家视角，演示知识库编辑即生效。每个镜头先说「顾客遇到什么」，再看「Agent 怎么调工具」，最后看「事有没有办成」。
> **技术看点**：LangGraph 6 节点多 Agent（Router / 澄清 / 售前 / 售后 / 投诉 / 终审）、10 个工具注册表（7 个客服工具 + 3 个运营向，MCP 暴露 4 个）、两段式敏感操作门控、RAG 引用溯源。
> **总时长 410s ≈ 7 分钟**（要求 5–8 分钟）。分段：一、顾客办事 220s｜二、商家维护与过程透明 110s｜三、架构与收尾 80s。
> **如实标注**：演示使用本地 20 单种子数据，未接淘宝/拼多多真实授权；退款只作用于种子库。

## 一、顾客办事（220s）

### 1. 开场：首页不是聊天框，是三条能直接跑的任务（25s）

- 触发：顾客打开客服页，不知道该从哪里问。
- 画面：`/chat` 空状态。标题「不只是聊天，是能把事办完」；下方 4 个技术 chip（LangGraph 6 节点 / 8 个工具 / RAG 43 篇 / 20 单演示数据）；「工作方式：路由判断意图 → 专业 Agent 调工具 → 终审校验防幻觉」；「3 分钟演示路线」三行：查订单 / 办退款 / 投诉建单，每行右侧一个「开始」按钮；最下方 4 张能力卡。
- 台词：「店智 Copilot 不是陪聊机器人。首页把三条最常办的事直接摆出来：查订单、办退款、投诉建单。顾客点『开始』就能跑，不用先学会怎么提问。背后是 LangGraph 多 Agent：先判断意图，再交给专业 Agent 调工具，最后终审校验。」
- 对应文件：`components/DemoGuide.tsx`、`components/ScenarioCards.tsx`

### 2. 查订单：一句单号，订单卡与物流摊开（50s）

- 触发：顾客买了保温饭盒，一周没动静，想知道到哪了。
- 画面：点路线「查订单」右侧「开始」，问题 `SO20261027009 到哪了？` 直接发送。右侧弹出「订单详情」抽屉：郑\*、不锈钢保温饭盒 ×2、¥178、已发货、圆通速递 `YT9182736455102`、时间线（下单/支付/发货）。
- Agent 动作：Router 判为售后，交给售后 Agent；售后 Agent 调 `order_lookup(order_id=SO20261027009)`，拿到状态与运单号后组织回答。
- 结果：回答给出商品、快递、运单号、收货地址，并提示可用运单号查实时轨迹。
- 台词：「顾客点『开始』，问题直接发出。Router 先判意图：这是售后。售后 Agent 调 order_lookup 查种子库，不是让模型凭记忆编物流。右边订单卡摊开：已发货、圆通、运单号、收货地址。查询结果直接变成下一步动作的上下文。」
- 对应文件：`backend/app/agent/graph.py`、`components/ChatWindow.tsx`、`components/OrderDetailCard.tsx`

### 3. 多 Agent 面板特写：路由、handoff、工具轨迹、终审（45s）

- 触发：顾客（和评审）想知道「这真是多 Agent，还是一个大模型在调工具？」
- 画面：放大回答上方的「多 Agent 处理过程」面板：
  1. 顶部徽章「售后 Agent 接手」+ 4 个专家花名册（售前 / 售后 / 投诉 / 澄清，售后高亮，其余灰显，右侧写「按意图选 1 个」）；
  2. Router Agent 一行：`置信度 0.97 · 情绪neutral`，下一行 `意图 aftersales`；
  3. `↳ Router → 售后 Agent（handoff）`；
  4. 售后 Agent 一行：`调用 1 次工具：order_lookup`，下面是工具轨迹与关键返回字段；
  5. Review Agent 一行：`通过 · 证据 1 条 · 引用 0 条`。
- 台词：「注意这块面板，它不是装饰。四个专家常驻，这一轮 Router 选了售后，其余三个灰掉，handoff 这一行就是路由交接。售后 Agent 调了什么工具、返回了哪些字段，原样写出来；最后 Review 做证据校验，没证据就拒答。单轮只命中一个专家，但路由决策、工具证据、终审裁决全程可见，不是黑盒。」
- 对应文件：`components/ThoughtChain.tsx`、`backend/app/agent/graph.py`

### 4. 退款两段式：先预览，顾客确认才动钱（65s）

- 触发：同一顾客想退 80 元。
- 画面：新建会话，点路线「办退款」的「开始」，发送 `订单 SO20261027001，帮我退 80 块`。回答给出预览：订单实付 159.8、本次退款 80、退款后剩余 79.8，并问「确认退款吗」。面板同步显示 `order_lookup` + `refund_flow(validate)` 两条工具轨迹。顾客回一句「确认」，出现执行回执：退款金额 80、剩余 79.8、售后单号、状态已退款、时间。
- Agent 动作：第一段 `refund_flow(validate)` 校验订单存在、已付款、未退过、金额不超实付、在售后期内，通过后签发 10 分钟有效的一次性令牌并停下等待；第二段 `refund_flow(execute)` 凭令牌落库。
- 台词：「退款是敏感操作，做成两段式。第一段只校验：订单在不在、付没付过、金额超没超、过没过售后期。全过了才发一张 10 分钟有效的一次性令牌，然后把预览摆出来等顾客确认。顾客说『确认』，第二段才真正执行。校验规则全在后端，模型说了不算；重复执行也只回已退款，不会重复扣钱。」
- 对应文件：`backend/app/agent/__init__.py`（`refund_flow`）、`backend/app/agent/graph.py`

### 5. 售前推荐：按预算查商品与库存（35s）

- 触发：顾客想给父母买礼物，预算 200 元以内。
- 画面：新建会话，点能力卡「售前推荐」，发送 `200 元以内送父母的礼物，有什么推荐？`。面板显示「售前 Agent 接手」、售前高亮，工具轨迹 `product_lookup(keyword=...)`，回答给出商品名、价格、库存，并追问使用对象与容量偏好。
- 台词：「售前走另一条支路。Router 选售前 Agent，它调 product_lookup 查价格和库存，回答里能看到具体商品、金额和剩余库存；信息不够时先追问，而不是硬推荐。」
- 对应文件：`backend/app/agent/graph.py`、`components/ScenarioCards.tsx`

### 6. 投诉建单：情绪识别 + 工单 + 处理方案（50s）

- 触发：顾客等了一周没到，情绪上来了。
- 画面：新建会话，点路线「投诉建单」的「开始」，发送 `等了一周还没到，太失望了，我要投诉！`。用户消息上方意图 chip 显示「意图：投诉升级 · 路由 → Agent 工具」，下方一枚「愤怒」情绪徽章。面板显示「投诉 Agent 接手」、投诉高亮、Router 置信度 0.97 / 情绪angry、handoff、`类别:物流配送 紧急度:high`、`已生成工单 TK-…`，Review 裁决「工单已受理 · 已转人工」。页头出现「投诉处理方案」按钮。
- 二次动作：点页头「投诉处理方案」，在弹窗里填一句诉求（如「物流一周未更新，顾客要求赔偿」）并点「生成处理方案」；弹窗关闭，对话区出现「投诉处理方案」卡片，分三块：情况摘要、建议动作、可复制话术。
- 台词：「Router 不只判意图，还识别情绪——angry 0.97。投诉 Agent 把对话压成工单：物流配送、紧急度 high，生成 TK 工单号，终审用安抚语气告知已受理。页头的『投诉处理方案』再补一刀：把情况摘要、建议动作和可复制话术整理出来，客服可以直接拿去回复。」
- 对应文件：`backend/app/agent/graph.py`、`components/EscalateDialog.tsx`、`backend/app/api_escalation.py`

## 二、商家维护与过程透明（110s）

### 7. 知识库编辑即生效（45s）

- 触发：商家发现知识库里退款率口径过时。
- 画面：切到 `/kb`，43 篇文档列表。打开《退款率过高的后果与控制》，把「一般建议将退款率控制在类目均值以内」改成「一般建议将退款率控制在 8% 以内」，点保存，状态回到「与索引一致」。回 `/chat` 问 `退款率控制在多少比较安全？`，回答给出 8%，句末带 `[1]`。
- 台词：「知识库不是只读 FAQ。改一句、点保存，这一块重新嵌入，旧检索立即失效；下一次提问直接读到新口径，不用重启服务。问答里的 `[1]` 还能点开看原文，回答有没有依据当场核对。」
- 对应文件：`app/kb/page.tsx`、`backend/app/rag/pipeline.py`、`backend/app/rag/retrieve.py`

### 8. 刷新不丢：会话与引用都能回查（30s）

- 触发：顾客隔天回来继续问。
- 画面：刷新整页，左侧会话列表与消息原样恢复；点回答里的 `[1]`，右下弹出引用卡片，显示标题、分类、原文片段。
- 台词：「会话存在本地 SQLite，刷新不丢；每个会话带 AGENT 标记。回答里的角标能点开来源卡片——哪句话来自哪篇文档，当场核对。这也是防幻觉的最后一道门。」
- 对应文件：`backend/app/store.py`、`lib/useSessions.ts`、`components/CitationCard.tsx`

### 9. 终审与拒答：没证据就不编（35s）

- 触发：评审问「模型胡说怎么办？」
- 画面：回到查订单会话，指 Review 行的「通过 · 证据 N 条」；再展示无工具、无引用的追问场景，Review 显示「追问放行（无工具）」或「拒答（无证据）」。
- 台词：「每个专家输出都要过终审：有工具证据才放行，有引用才允许带角标；没证据就走拒答或追问，不硬编。工具异常也不把报错甩给顾客，会转成可读提示，让模型换路径。」
- 对应文件：`backend/app/agent/graph.py`（review 节点）

## 三、架构与收尾（80s）

### 10. 分层架构：AI 能力只在 FastAPI 一层（35s）

- 画面：分层图逐行浮现，高亮「AI 能力唯一接入层」。
- 台词：「前端 Next.js 只负责交互，问答、Agent、检索、视觉全部收在 FastAPI 一层。浏览器不直连模型，密钥只在 Python 端；同源代理把 `/api/*` 转到后端，既过比赛规则，也守住密钥。」
- 对应文件：`backend/app/main.py`、`app/api/v1/[...path]/route.ts`

```
浏览器 Next.js 16（流式对话 · 多 Agent 面板 · 引用角标 · 语音/图片）
 │  同源代理 /api/agent · /api/vision · /api/v1/*
 ▼
FastAPI  backend/app/          ← AI 能力唯一接入层
 ├── LangGraph 6 节点：Router / Clarify / Presales / Aftersales / Escalation / Review
 ├── 工具注册表 10 个（7 个客服 + 3 个运营向）· MCP 独立进程暴露 4 个
 ├── RAG：jieba BM25 + fastembed + LanceDB（43 篇语料）
 └── SqliteSaver 会话检查点 · DataProvider 取数（sqlite / mock 可切）
 ▼
外部：DeepSeek API · GLM-4V（可选）
```

### 11. 关键决策：为什么这样搭（25s）

- 画面：四张字卡依次切换。
- 台词：「四个决策。第一，用 LangGraph 而不是手写循环：多 Agent 路由、检查点、人工确认都好表达。第二，检索走 BM25 加向量的混合召回，RRF 融合。第三，数据接入做成 Provider 插件，换真实店铺只改一个类和一个环境变量。第四，敏感操作统一 validate → 确认 → execute，模型不直接动钱。」
- 对应文件：`backend/app/agent/graph.py`、`backend/app/rag/retrieve.py`、`backend/app/agent/data_provider.py`

### 12. 质量数字 + 收尾（20s）

- 画面：数字卡依次定格：43 篇语料 / 12 段场景 / 20 单种子；检索自测 90%（9/10）；RAG 评测 v2 29/30（无 RAG 30/30，增量在私有规则与引用）；冒烟 9/9；tsc / eslint / build 全绿。底部常驻字条「本地模拟数据，未接平台真实授权」。
- 台词：「质量用数字说话：检索自测 90%，RAG 评测 29 比 30——无 RAG 在通用常识题上也很强，RAG 的增量在平台私有规则、知识库口径和引用可溯源。冒烟 9/9，前端构建与类型检查全绿。演示跑的是本地种子数据，未接平台真实授权；要接真实店铺，实现 DataProvider 契约就行。店智 Copilot，面向客户的电商智能客服 Agent——咨询即办理。」
- 对应文件：`backend/app/rag/selftest.py`、`docs/rag-eval-v2.md`、`scripts/smoke.mjs`

## 与同类系统对比定位

| 维度 | 同类客服系统 | 店智 Copilot |
|---|---|---|
| 多 Agent | 宣传"智能路由"，界面只看到一次回答 | **4 专家花名册 + Router 意图 + handoff + 工具轨迹 + 终审裁决** |
| 办理能力 | 查询后跳工单/转人工 | **对话内完成退款/改址/拦截/退换**，两段式门控 |
| 退款操作 | 后台表单或人工 | **对话内 validate → 预览 → 顾客确认 → execute 回执** |
| 过程透明 | 事后日志 | **面板逐轮留痕**：谁接手、调了什么、返回什么、终审是否放行 |
| 知识来源 | 展示来源列表 | **`[1]` 角标 + 点击弹出原文卡片** |
| 知识库管理 | 版本发布/回滚 | **编辑即生效**（保存→重嵌入→检索失效，一分钟） |
| 人工客服 | 转人工接管 | 投诉建单转人工，其余在对话内闭环 |
