# 店智 Copilot 5 分钟口播稿（可直接照读）

> 用法：只读「口播」里的文字，【画面】是动作提示，不读。全稿约 1200 字，按每分钟 240–260 字朗读，配合操作停顿，正好 5 分钟左右。
> 录制顺序与稿件一致。退款镜头拍完要恢复种子库；知识库镜头拍完把 8% 改回类目均值。

---

## 0:00–0:25 开场

【画面】打开 `http://localhost:3000/chat`，停在首页空状态，鼠标轻扫三条演示路线。

【口播】
这是店智 Copilot，一个面向电商客户的智能客服 Agent。它不是陪聊机器人，而是把查订单、办退款、投诉建单这些事，直接在一个对话框里办完。系统有两个业务入口：顾客侧的客服对话，和商家侧的知识库，另有一个系统概览页。先看顾客侧，点「查订单」的开始。

---

## 0:25–1:10 查订单

【画面】点「01 查订单」右侧「开始」，问题自动发送。等回答出现后，把右侧订单详情抽屉缓慢滚一遍：商品、金额、状态、物流、运单号。

【口播】
顾客问：SO20261027009 到哪了？Router 先判断意图，这是售后，交给售后 Agent。售后 Agent 调用 order_lookup 查种子库，而不是让模型凭记忆编物流。右边订单卡自动展开：郑先生、不锈钢保温饭盒两件、实付 178、已发货、圆通速递，运单号 YT9182736455102。回答里还会提示，可以用这个单号查实时轨迹。

---

## 1:10–1:40 多 Agent 面板

【画面】鼠标移到回答上方的「多 Agent 处理过程」，依次指四个专家、Router 行、handoff 行、工具轨迹、Review 行。

【口播】
注意回答上方的「多 Agent 处理过程」。四个专家常驻，这一轮售后高亮，其余灰掉；Router 给出置信度和情绪，handoff 这一行就是路由交接。售后 Agent 调了什么工具、返回了哪些字段，原样写出来；最后 Review 做证据校验。单轮只命中一个专家，但路由、工具、终审全程可见，不是黑盒。这也是它和单个大模型调工具的区别：决策过程可解释。

---

## 1:40–2:40 退款两段式

【画面】新建会话，点「02 办退款」的「开始」。等预览出现，停顿两秒，再输入「确认」发送。等回执出现，指一下退款金额、剩余、售后单号。

【口播】
再看退款。新建会话，点「办退款」，发送：订单 SO20261027001，帮我退 80 块。第一段只做校验：订单在不在、付没付过、金额超没超、过没过售后期。通过后发一张十分钟有效的一次性令牌，然后把预览摆出来：实付 159.8，本次退 80，剩余 79.8，问顾客确认吗。顾客回「确认」，第二段才真正执行，返回售后单号和回执。校验规则全在后端，模型说了不算；重复执行也只回已退款，不会重复扣钱。退款、改地址、拦截物流、退换货，四类敏感操作都是同一套门控。

---

## 2:40–3:05 售前推荐

【画面】新建会话，点「售前推荐」能力卡，问题自动发送。回答出现后，指一下商品名、价格、库存。

【口播】
售前走另一条支路。点「售前推荐」，顾客说 200 元以内送父母。Router 选售前 Agent，调用 product_lookup 查价格和库存，回答给出具体商品、金额和剩余库存；信息不够时先追问，而不是硬推荐。

---

## 3:05–3:50 投诉建单与处理方案

【画面】新建会话，点「03 投诉建单」的「开始」。回答出现后，指意图 chip、投诉 Agent、工单号、Review。再点页头「投诉处理方案」，输入一句诉求，提交，展示摘要/建议/话术卡片。

【口播】
投诉场景。顾客说等了一周还没到，太失望了。Router 识别出投诉和愤怒情绪，投诉 Agent 把对话压成工单：物流配送、紧急度 high，生成 TK 开头的工单号，终审用安抚语气告知已受理。页头出现「投诉处理方案」，点开，填一句诉求，生成情况摘要、建议动作和可复制话术。客服可以直接拿去回复。

---

## 3:50–4:25 知识库编辑即生效

【画面】切到 `/kb`，打开《退款率过高的后果与控制》，把口径改成 8%，保存。回 `/chat` 提问「退款率控制在多少比较安全？」，等回答后点 `[1]` 展示来源卡片。

【口播】
商家侧在知识库。这里 43 篇文档，打开退款率这篇，把口径改成 8%，保存。切片重新嵌入，旧检索立即失效。回到对话问：退款率控制在多少比较安全？回答给出 8%，句末带 [1]，点开能看原文。知识库不是只读 FAQ，改一句，下一次提问就生效，不用重启服务。

---

## 4:25–4:50 架构与质量

【画面】切回 `/chat`，展示左侧三个入口（客服对话 / 知识库 / 系统概览）；可叠一张架构图或字卡。最后停在数字卡。

【口播】
架构上，前端只做交互，问答、Agent、检索全部收在 FastAPI 一层，浏览器不直连模型，密钥只在 Python 端。图里有六个节点：Router、澄清、售前、售后、投诉、终审；会话用 SqliteSaver 持久化，刷新不丢。质量用数字说话：检索自测 90%，RAG 评测 29 比 30，冒烟 9 比 9，类型检查、lint、构建全绿。

## 录制前检查（不读）

- 后端必须用 Anaconda Python：`C:\Users\z\anaconda3\python.exe -m uvicorn backend.app.main:app --port 8000`；系统默认 `python` 会缺 `langgraph.checkpoint.sqlite`。
- 前端已启动在 `http://localhost:3000`（生产模式，`next start`）。
- 录前备份种子库：`Copy-Item data\store.db data\store.demo.bak -Force`；退款镜头每拍一条前恢复，避免 001 已退款导致预览失败。
- 清空会话栏，关闭无关标签；建议 1440×900 或 1920×1080，100% 缩放。
- 退款必须发第二轮「确认」才出回执；投诉每次生成新工单号属正常；投诉方案要再点页头按钮并填一句诉求。
- 知识库拍完把「8%」改回「类目均值」并保存，或点「重建索引」复位。
