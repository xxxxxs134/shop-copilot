# 店智 Copilot 5 分钟口播稿（可直接照读）

> 用法：只读「口播」里的文字，【画面】是动作提示，不读。全稿约 1200 字，按每分钟 240–260 字朗读，配合操作停顿，正好 5 分钟左右。
> 录制顺序与稿件一致。本演示会执行一次物流拦截，`SO20261027007` 从 `shipped` 变为 `intercepted`；录前备份 `data/store.db`，录后恢复。退款只做只读预检。知识库后台镜头拍完把 8% 改回类目均值。

## 0:00–0:25 开场

【画面】打开 `http://localhost:3000/chat`，停在首页空状态，鼠标轻扫三条演示路线。

【口播】
这是店智 Copilot，一个直接服务顾客的电商智能客服 Agent。拦截物流、退款受阻诊断、投诉建单，顾客都在这一个对话框里推进，Agent 当场给结果。商品知识和售后规则在后台维护，保证回答有据；顾客用的只有这个对话入口。先看顾客视角，点「拦截物流」的开始。

---

## 0:25–1:15 拦截物流：首轮校验，手输确认后执行

【画面】点「01 拦截物流」右侧「开始」，问题自动发送。等回答出现后，把右侧订单详情抽屉缓慢滚一遍：商品、金额、已发货状态、顺丰运单号、原地址。然后回到输入框，手动输入「确认拦截」并发送。执行成功后，指订单抽屉的「已拦截」状态；点开「多 Agent 处理过程」指 Review 行。

【口播】
顾客问：SO20261027007 地址填错了，已经发货了，能帮我拦截吗？Router 先判断意图，这是售后，交给售后 Agent。售后 Agent 先调 order_lookup 查订单，再调 intercept_logistics 做拦截校验，不是让模型凭记忆编物流。右边订单卡自动展开：周先生、纯棉基础款 T 恤加桌面收纳盒、实付 129.8、已发货、顺丰速运，运单号 SF7392846152738，还有原地址。第一轮只校验、不执行，回答请顾客确认。顾客手动输入「确认拦截」，Agent 重新校验令牌后执行，状态变成已拦截。敏感操作必须客户确认，模型不能自己动。

---

## 1:15–1:45 多 Agent 面板

【画面】点开回答上方的「多 Agent 处理过程」（默认折叠），依次指四个专家、Router 行、handoff 行、工具轨迹、Review 行。

【口播】
注意回答上方的「多 Agent 处理过程」。四个专家常驻，这一轮售后高亮，其余灰掉；Router 给出置信度和情绪，handoff 这一行就是路由交接。售后 Agent 调了什么工具、返回了哪些字段，原样写出来；首轮是校验，第二轮是执行。最后 Review 做证据校验。单轮只命中一个专家，但路由、工具、终审全程可见，不是黑盒。这也是它和单个大模型调工具的区别：决策过程可解释。

## 1:45–2:40 退款受阻

【画面】新建会话，点「02 售后异常」的「开始」。等回答出现后，指一下订单卡、售后单状态「被拒」、知识库引用 `[1]`。

【口播】
再看退款受阻。平台订单页已经支持顾客自助申请退款，所以这里不替顾客执行退款，也不越权碰资金。顾客的申请被拒了，Agent 先调 order_lookup 查订单和售后单，确认这单已收货、退款状态是被拒；再查知识库里的退款政策，告诉她可能的原因、还缺什么证据，以及下一步是回订单页重新申请、发起申诉，还是升级投诉。退款动作留在平台，Agent 负责把规则和路径讲清楚。

## 2:40–3:05 售前推荐

【画面】新建会话，点「售前推荐」能力卡，问题自动发送。回答出现后，指一下商品名、价格、库存。

【口播】
售前走另一条支路。点「售前推荐」，顾客说 200 元以内送父母。Router 选售前 Agent，调用 product_lookup 查价格和库存，回答给出具体商品、金额和剩余库存；信息不够时先追问，而不是硬推荐。

## 3:05–3:50 投诉建单与处理方案

【画面】新建会话，点「03 投诉建单」的「开始」。回答出现后，指意图 chip、投诉 Agent、工单号、Review。再点页头「投诉处理方案」，输入一句诉求，提交，展示摘要/建议/话术卡片。

【口播】
投诉场景。顾客说等了一周还没到，太失望了。Router 识别出投诉和愤怒情绪，投诉 Agent 把对话压成工单：物流配送、紧急度 high，生成 TK 开头的工单号，终审用安抚语气告知已受理。页头出现「投诉处理方案」，点开，填一句诉求，生成情况摘要、建议动作和可复制话术，Agent 拿着这份方案直接回复顾客，把安抚和后续处理讲清楚。

【口播】
顾客的回答有没有据，看这里。知识库后台有 43 篇文档，打开退款率这篇，把口径改成 8%，保存。切片重新嵌入，旧检索立即失效。回到对话问：退款率控制在多少比较安全？回答给出 8%，句末带 [1]，点开能看原文。改一句，顾客下一次提问就得到新口径，不用重启服务。

## 4:25–4:50 架构与质量

【画面】切回 `/chat`，展示左侧三个入口（客服对话 / 知识库后台 / 系统概览）；可叠一张架构图或字卡。最后停在数字卡。

【口播】
架构上，前端只做交互，问答、Agent、检索全部收在 FastAPI 一层，浏览器不直连模型，密钥只在 Python 端。图里有六个节点：Router、澄清、售前、售后、投诉、终审；会话用 SqliteSaver 持久化，刷新不丢。质量用数字说话：检索自测 90%，RAG 评测 29 比 30，冒烟 10 比 10，类型检查、lint、构建全绿。

## 录制前检查（不读）

- 后端必须用 Anaconda Python：`C:\Users\z\anaconda3\python.exe -m uvicorn backend.app.main:app --port 8000`；系统默认 `python` 会缺 `langgraph.checkpoint.sqlite`。
- 前端已启动在 `http://localhost:3000`（生产模式，`next start`）。
- 首条拦截会真实改种子库：录前备份 `data/store.db`，录后恢复；如需重置会话，备份/恢复 `data/app.db`。
- 清空会话栏，关闭无关标签；建议 1440×900 或 1920×1080，100% 缩放。
- 首条拦截必须由顾客手动输入 `确认拦截`；演示路线只发首轮问题，不会自动发第二轮。
- 退款受阻镜头不执行退款，只展示订单/售后状态、政策依据与申诉路径；投诉每次生成新工单号属正常；投诉方案要再点页头按钮并填一句诉求。
- 知识库拍完把「8%」改回「类目均值」并保存，或点「重建索引」复位。
